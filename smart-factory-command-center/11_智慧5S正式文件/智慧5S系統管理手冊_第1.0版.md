## 一、這本手冊怎麼用

### 1.1 使用目的

本手冊規範智慧 5S 管理平台第 1.0.2 版的帳號與角色、中央資料庫、主檔、PWA、Apps Script、LINE 通知、離線同步、監控、備份、故障處理、變更發布與復原。它是系統維護與交接的正式依據，不取代現場操作、主管判定或 5S 管理制度。

### 1.2 管理範圍

| 管理層 | 正式元件 | 管理重點 | 主要證據 |
|---|---|---|---|
| 使用者端 | `docs/5s/` PWA、Manifest、Service Worker | 版本、快取、安裝、離線與介面 | Git 提交、驗收報告、實機截圖 |
| 服務端 | 智慧製造中央作戰指揮中心 Apps Script | API、路由、Web App 部署、執行紀錄 | 部署版本、執行紀錄、健康檢查 |
| 資料層 | `⭐智慧工廠主資料庫` | 人員、區域、清單、交易資料與統計 | 備份、欄位稽核、單號與時間戳 |
| 通知層 | 既有 NEXUS OS 唯一 LINE Bot | 收件群組、待通知、觸發器與錯誤 | 通知紀錄、群組收件、執行紀錄 |
| 版本層 | GitHub `smart-factory-worker-app` | 變更審查、發布、回復與文件同步 | 分支、提交、Pages 部署結果 |
| 裝置層 | 瀏覽器快取、Local Storage、IndexedDB | 登入快取、分頁快取與待同步佇列 | 裝置識別碼、待同步筆數、處理紀錄 |

### 1.3 管理角色與責任

| 角色 | 可以做 | 必須共同確認 | 不得做 |
|---|---|---|---|
| 系統管理員 | 統籌設定、版本、事件與復原 | 與資料、GAS、LINE 維護者核對影響 | 未留備份直接改正式環境 |
| 資料管理員 | 維護人員、區域、檢查項目與核准資料修正 | 欄名、主鍵、關聯、原值與新值 | 刪除交易列、插入錯位欄位、改日期掩蓋逾期 |
| Apps Script 管理員 | 維護模組、屬性、部署與觸發器 | 路由、權限、正式網址與回歸測試 | 把權杖寫入程式碼或另建第二套後端 |
| GitHub 維護者 | 維護 PWA 與文件、發布 Pages | 版本號、快取鍵、驗收與回復點 | 跳過測試直接推送未核准程式 |
| LINE Bot 管理員 | 維護既有 Bot、群組對應與通知排程 | 收件人、權杖存在性與測試範圍 | 複製權杖、挪用未確認群組或建立第二個 Bot |
| 業務核准者 | 核准主檔、權限、停機與重大修復 | 影響範圍、風險、回復方案 | 要求技術人員無紀錄改正式資料 |

> 同一人可以兼任多個角色，但核准與執行仍應留下可追溯紀錄。重大資料修正、正式部署、權限提升與通知收件人變更至少要有提出人與核准人。

### 1.4 管理員十項禁令

1. 不建立第二份 5S 正式試算表、第二個 Web App、第二個 PWA 入口或第二個 LINE Bot。
2. 不把 `LINE_CHANNEL_ACCESS_TOKEN`、登入憑證或私人金鑰寫入 Git、試算表或操作手冊。
3. 不直接刪除巡檢、改善、紅牌、通知或歷程資料列。
4. 不插入、移動或改名正式資料表欄位；欄位變更必須同步修改程式與驗收。
5. 不用直接改期限、狀態或分數的方式美化績效。
6. 不在裝置仍有待同步資料時清除瀏覽器網站資料、IndexedDB 或解除安裝 PWA。
7. 不同時啟用兩套 5S LINE 待通知排程，避免重複推播。
8. 不以正式寫入驗收程式代替日常健康檢查。
9. 不用強制覆蓋或重寫 Git 歷史處理正式版問題。
10. 不在沒有回復點、負責人與驗證清單時進行正式變更。

### 1.5 維護前六十秒檢查

- [ ] 已確認本次是查核、主檔維護、程式發布、資料修復或事件處理。
- [ ] 已記錄正式版本第 1.0.2 版與目前 Git 提交識別碼。
- [ ] 已確認正式入口、GAS Web App 與中央資料庫識別碼。
- [ ] 已建立或確認可用備份，且不會覆蓋唯一可回復版本。
- [ ] 已確認沒有裝置仍在大量離線作業或等待同步。
- [ ] 已準備驗證步驟、失敗停止條件與回復方式。

### 2.2 資料流

1. 使用者由 GitHub Pages 開啟 PWA，首次登入在線讀取 `01_人員主檔`。
2. PWA 以 `sheetData` 讀取人員、區域、檢查項目與各交易分頁。
3. 新增資料以 `appendRow` 寫入；既有改善或紅牌狀態以 `updateRow` 更新。
4. 網路錯誤或離線時，可排隊的工作依序存入本機 IndexedDB `待同步佇列`。
5. 網路恢復後，PWA 依建立時間逐筆補送，成功即移出佇列，失敗則保留錯誤與嘗試次數。
6. 重大異常與新紅牌先寫入 `5S_通知紀錄`，再由既有 NEXUS OS 唯一 LINE Bot 橋接處理。
7. GitHub `main` 的 `docs/` 由 Pages 工作流程發布；GAS 必須另在 Apps Script 正式部署中升版。

### 2.3 唯一來源規則

| 資料類型 | 唯一正式來源 | 禁止的替代來源 |
|---|---|---|
| 人員與角色基礎 | `01_人員主檔` | 另建 5S 帳號表或私人名單 |
| 區域與清單 | `5S_區域主檔`、`5S_檢查項目` | 裝置本機固定名單或複製試算表 |
| 巡檢與改善交易 | 中央資料庫各 `5S_` 交易分頁 | 聊天訊息、紙張或離線裝置作為最終帳 |
| PWA 程式 | GitHub `main`／`docs/5s/` | 未提交的本機檔案或臨時網址 |
| GAS 程式 | 已核准 Git 版本與正式 Apps Script 部署 | 個人 Apps Script 複本 |
| LINE 發送 | 既有 NEXUS OS 唯一 Bot | 第二組權杖或另一個 Bot |
| 正式文件 | `11_智慧5S正式文件` 對應版本 | 未標版本的舊附件 |

### 2.4 第 1.0.2 版實際邊界

| 項目 | 第 1.0.2 版實際狀態 | 管理要求 |
|---|---|---|
| 角色判定 | 由前端依人員職稱與角色類型判定 | 這是介面功能控制，不應視為完整的服務端授權邊界 |
| `5S_系統參數` | 初始化會建立預設值，但 PWA 目前不會動態讀取 | 改此分頁不會自動改變前端期限、分數或照片上限 |
| 照片 | PWA 壓縮至約 42,000 字元後寫入試算表 | GAS 的 Drive 儲存函式已存在，但尚未接到正式 PWA 流程 |
| 戰情 | PWA 主要由各分頁資料在前端計算 | GAS 另有戰情動作，不等於首頁一定直接呼叫該動作 |
| 非必要品處置 | 資料分頁與後端規格已存在 | 第 1.0.2 版 PWA 沒有獨立處置單維護畫面，不得假定自動建單 |

## 三、帳號、角色與存取安全

### 3.1 人員主檔最低欄位

登入至少依賴 `工號` 與 `姓名`；使用者資料還會讀取 `部門`、`組別`、`職稱`、`班別` 與 `啟用`。主資料庫既有規格另含 `LINE_USER_ID`、`備註` 與 `更新時間`。

| 欄位 | 管理規則 | 常見風險 |
|---|---|---|
| 工號 | 唯一、完整、不得重複，建議以文字格式保存 | 前導零消失、空白、重複或被轉成數字 |
| 姓名 | 使用正式姓名；同名人員仍以工號登入 | 部分姓名比對可能先找到非預期人員 |
| 部門／組別 | 與現場責任一致 | 戰情與交接責任錯置 |
| 職稱 | 使用核准職稱 | 會直接影響前端角色判定 |
| 角色類型 | 若表內已有此欄，使用受控值 | 非標準文字造成判定不一致 |
| 啟用 | 使用「否」停用；其他值在前端視為可用 | 空白仍可能被視為啟用 |
| 更新時間 | 每次核准異動後更新 | 無法追溯權限何時變更 |

### 3.2 角色判定規則

| 條件 | 前端系統角色 | 可見管理動作 |
|---|---|---|
| 職稱含營運長、總經理、經理、副理、課長、主任、主管，或角色類型含主管 | 主管 | 改善驗證、駁回與紅牌結案 |
| 職稱含工程師、助理工程師、領班、組長，或角色類型含幹部 | 區域負責人 | 改善驗證、駁回與紅牌結案 |
| 其他 | 現場人員 | 巡檢、改善送驗與開始紅牌處理 |

> 角色規則寫在 `智慧5S應用程式.js`。修改關鍵字會影響所有使用者，必須依正式程式發布流程處理，不能只改文件或試算表說明。

### 3.3 新增或異動人員

1. 取得人員主管核准的工號、姓名、部門、組別、職稱、班別與啟用狀態。
2. 在 `01_人員主檔` 搜尋完整工號，確認沒有重複列。
3. 新增或更新資料；不得改動表頭與其他人員欄位。
4. 填寫備註與更新時間，保留異動原因與核准人。
5. 請使用者在線登出後重新登入。
6. 到設定頁核對姓名、工號、部門、職稱與系統角色。
7. 若是管理角色，以一筆非正式驗證案例確認按鈕顯示；不得為測試直接結案正式案件。

### 3.4 停用人員

1. 先盤點其未結改善、驗證中案件、紅牌責任與未完成交接。
2. 由主管指定新責任人；需變更交易資料時走授權資料修正流程。
3. 將 `01_人員主檔.啟用` 設為「否」，保留原人員資料，不刪列。
4. 記錄停用日期、原因、執行人與核准人。
5. 已登入裝置的本機使用者快取不會主動遠端清除，應要求本人或裝置管理員登出。
6. 抽查停用工號在線登入會顯示「此人員目前已停用」。

### 3.5 權限異常處理

| 現象 | 查核順序 | 修正後驗證 |
|---|---|---|
| 找不到工號或姓名 | 工號格式 → `啟用` → API 表頭與資料列 → 前端資料修復解析 | 在線清快取後重新登入 |
| 角色過高 | 職稱 → 角色類型 → 本機舊登入快取 | 更正主檔、登出重登、確認管理按鈕消失 |
| 角色過低 | 職稱與角色類型是否符合規則 | 更正主檔、登出重登、確認正確角色 |
| 顯示別人姓名 | 公用裝置未登出或部分姓名比對 | 立即停止作業、登出並以完整工號重登 |
| 停用後仍在系統內 | 裝置沿用 Local Storage 登入快取 | 由裝置端登出；必要時在待同步為 0 後清除網站資料 |

### 3.6 祕密與 Google 權限

- `LINE_CHANNEL_ACCESS_TOKEN` 只能存放在既有 LINE GAS 專案的 Script Properties，檢查是否存在即可，不讀出、不複製。
- `智慧製造_SPREADSHEET_ID` 可存於主 GAS 的 Script Properties；未設定時 5S 模組會使用正式預設識別碼。
- Apps Script Web App 目前設定為部署者身分執行並允許匿名存取。前端角色按鈕不是完整的服務端身分驗證，應以最小資料暴露、限定路由、變更稽核與後續服務端授權強化降低風險。
- 試算表與 Apps Script 編輯權限只給實際維護者；一般使用者只使用 PWA，不直接取得正式資料表編輯權。
- 離職、調職或委外結束時，同步移除 Google、GitHub、Apps Script 與 LINE 管理權限。

### 3.7 每月存取複核

- [ ] 人員主檔的停用狀態與在職名單一致。
- [ ] 主管與區域負責人名單均有業務主管核准。
- [ ] 試算表、Apps Script、GitHub 與 LINE 管理者沒有離職或不必要帳號。
- [ ] 沒有權杖、識別碼以外的祕密出現在原始碼、Issue、文件或聊天紀錄。
- [ ] 公用裝置已遵守個人登入、收班登出與待同步歸零。

## 四、中央資料庫與分頁治理

### 4.1 十五張必要分頁

正式驗收範圍是 `01_人員主檔` 加上十四張 `5S_` 分頁，共十五張。

| 分頁 | 主要用途 | 主鍵／追溯鍵 | 日常人工維護 |
|---|---|---|---|
| `01_人員主檔` | 登入與角色基礎 | 工號 | 核准後可維護 |
| `5S_區域主檔` | 區域、責任、清單與 LINE 群組 | 區域代碼 | 核准後可維護 |
| `5S_檢查項目` | 5S 類別、順序、內容與標準 | 項目代碼 | 核准後可維護 |
| `5S_系統參數` | 預設參數與版本紀錄 | 參數鍵 | 只作受控參照；目前不動態套用前端 |
| `5S_巡檢主檔` | 每張巡檢單的總分與狀態 | 巡檢單號 | 原則上不可直接改 |
| `5S_巡檢明細` | 每一檢查項目的得分與異常證據 | 明細編號 | 原則上不可直接改 |
| `5S_改善單` | 責任、期限、狀態、照片與驗證 | 改善單號 | 只走 PWA 或核准修正 |
| `5S_改善歷程` | 改善狀態與說明軌跡 | 歷程編號 | 只新增，不覆蓋既有歷程 |
| `5S_全物品盤點` | 必要性、頻率與紅牌需求 | 盤點編號 | 只走 PWA 或核准修正 |
| `5S_紅牌追蹤` | 暫存、處置期限、狀態與證據 | 紅牌編號 | 只走 PWA 或核准修正 |
| `5S_非必要品處置` | 正式處置、會辦、核准與憑證 | 處置單號 | 第 1.0.2 版無獨立 PWA 畫面 |
| `5S_照片` | 照片中繼資料與壓縮照片資料 | 照片編號 | 不直接編輯照片內容 |
| `5S_通知紀錄` | LINE 待發送、結果、錯誤與去重資訊 | 通知編號 | 只限通知修復流程 |
| `5S_區域日統計` | 每日區域平均、異常與完成率 | 日期＋區域代碼 | 由自動化重建 |
| `5S_排名快照` | 區域日排名快照 | 期間＋對象代碼 | 由自動化重建 |

### 4.2 初始化函式會做什麼

`智慧5S_初始化_()` 會在中央資料庫建立缺少的十四張 `5S_` 分頁、檢查並重寫各分頁前段表頭、凍結第一列、套用表頭格式、自動調整欄寬，並在空白的 `5S_系統參數` 寫入五個預設參數。

> 初始化不是日常修復按鈕。若現有表頭被插欄、改名或順序錯誤，函式可能重寫第一列而讓既有資料意義與欄名錯位。正式資料庫執行前一定要先複製備份、比對表頭與評估資料列。

### 4.3 安全初始化程序

1. 宣告維護時段，暫停 PWA 新增、更新與離線補送。
2. 複製完整中央試算表作為不可編輯備份，記錄備份時間與檔案識別。
3. 匯出或記錄十五張必要分頁的名稱、欄數、列數與第一列表頭。
4. 先在測試複本執行 `智慧5S_初始化_()`。
5. 比對分頁、表頭、資料列、下拉驗證、公式與權限是否完整。
6. 只有缺少空白分頁或經核准的表頭修復才在正式資料庫執行。
7. 執行後立刻跑健康檢查與唯讀驗收，抽查既有單號回讀。
8. 確認無誤才解除維護；若資料與欄名錯位，立即停止寫入並依備份復原。

1. 取得區域名稱、代碼、部門、責任人、巡檢頻率與檢查清單的核准。
2. 確認區域代碼、名稱與現有資料沒有重複或近似混淆。
3. 先建立或確認對應的啟用檢查項目。
4. 在 `5S_區域主檔` 新增一列，LINE 群組未確認時保持空白。

|---|---|---|
| 項目代碼 | 全表唯一、發布後固定 | 變更代碼會中斷歷史關聯 |

| 順序 | 使用可排序數字 | 重複順序需確認畫面排列 |
| 檢查內容 | 一次描述一個可觀察事實 | 避免一句含多個無法一致評分的要求 |
| 判定基準 | 可看、可量或可核對 | 不使用「適當」、「良好」等無客觀定義文字 |
| 最高分 | 正式四級評分以 5 分為最高 | 變更前需同步評分與計算設計 |
| 權重 | 使用核准數值 | 變更需驗證得分率與歷史可比性 |
| 拍照規則 | 與現場證據要求一致 | 異常低於 5 分仍由前端強制照片 |
| 啟用 | 「否」停用，不刪除歷史項目 | 停用前確認進行中的巡檢與教育 |

## 五、交易資料與資料修正

### 5.1 交易資料原則

巡檢、明細、改善、歷程、盤點、紅牌、照片與通知都是追溯紀錄。正常流程只由 PWA 或受控自動化新增、更新；管理員不以刪列、搬欄或重寫原始事實的方式修正。

### 5.2 可以修正與不可修正

| 情境 | 正確處理 | 不可接受 |
|---|---|---|
| 錯別字但不影響判定 | 依核准資料修正，保留原值、新值與原因 | 無紀錄直接覆蓋 |
| 錯區、錯人或錯期限 | 停止流程，評估關聯資料後做成組修正 | 只改一張表造成關聯不一致 |
| 重複送出 | 比對單號、時間、裝置與內容，保留一筆有效並封存重複 | 直接刪列讓歷程消失 |
| 分數或照片不實 | 依管理辦法作廢或補充說明 | 改分數美化結果、換掉原照片 |
| 狀態錯跳 | 依改善歷程與證據恢復合法狀態 | 只改改善單，不補歷程 |
| 統計錯誤 | 修正來源後重建日統計與排名 | 直接改統計數字 |

### 5.3 授權資料修正七步驟

1. 記錄事件編號、資料分頁、主鍵、現況與發現時間。
2. 暫停對該案件的後續操作與相關裝置同步。
3. 建立中央資料庫快照，保存原始列與關聯列。
4. 由資料管理員提出原值、新值、原因、影響分頁與驗證方法。
5. 經業務主管與系統管理員核准後，由指定人員執行。
6. 同步補足歷程或修正紀錄，不抹除原始事實。
7. 清除相關快取、重新讀取並驗證單號、狀態、統計與通知。

### 5.4 關聯修正檢查

| 主資料 | 必須一起查核的關聯 |
|---|---|
| 巡檢單號 | 巡檢主檔、巡檢明細、改善單來源、照片與通知 |
| 改善單號 | 改善單、改善歷程、巡檢明細、紅牌與照片 |
| 盤點編號 | 全物品盤點、紅牌追蹤與照片 |
| 紅牌編號 | 紅牌追蹤、改善單、非必要品處置、通知與實體紅牌 |
| 通知編號 | 通知狀態、送出時間、錯誤、收件群組與 LINE 收件結果 |
| 區域代碼 | 區域主檔、巡檢、改善、照片、統計與排名 |

### 5.5 `updateRow` 的服務端限制

第 1.0.2 版 `updateRow` 只接受名稱以 `5S_` 開頭的分頁，列號必須是大於等於 2 的既有整數列，並依正式表頭對齊指定欄位。執行時使用 Script Lock 最多等待 30 秒，避免同時更新造成錯列。

| 錯誤訊息 | 代表原因 | 管理處理 |
|---|---|---|
| 只允許更新 `5S_` 分頁 | 嘗試更新人員主檔或其他模組 | 使用核准的主檔維護方式，不繞過限制 |
| `rowNumber` 必須是大於等於 2 的整數 | 本機資料缺列號或參數錯誤 | 重新讀取資料後再操作 |
| 找不到分頁 | 名稱錯誤或分頁缺少 | 停止寫入並執行健康檢查 |
| `rowNumber` 超出資料範圍 | 列被刪除、快取過舊或指向錯誤資料庫 | 不重試原更新；先比對主鍵與備份 |
| 沒有可更新的 5S 欄位 | 欄名不在正式表頭 | 比對版本、欄名與前端欄位陣列 |

### 5.6 統計資料重建

`智慧5S_產生日統計_()` 會刪除當日既有統計列，再依啟用區域、非作廢巡檢與改善狀態重建 `5S_區域日統計`，接著重建當日 `5S_排名快照`。執行前應先修正來源資料，不能把統計重建當作掩蓋來源錯誤的方法。

1. 確認日期與 Apps Script 時區為 `Asia/Taipei`。
2. 抽查當日巡檢、區域代碼、作廢狀態與改善案件。
3. 執行 `智慧5S_產生日統計_()`。
4. 核對回傳日期、區域數與完成訊息。
5. 抽查至少一區的平均得分率、異常項數、未結與已結件數。
6. 核對排名快照名次與同分處理是否符合目前排序結果。

### 6.4 前端發布流程

1. 建立變更單，定義目的、影響檔案、資料影響、測試與回復方案。
2. 從最新 `main` 建立工作分支或受控工作版本，不直接在正式發布點試改。
3. 完成程式與文件修改，確認不含權杖、測試帳號或正式個資。
4. 執行本機唯讀驗收；無網路可先加 `--略過線上`，正式發布前仍要完成線上查核。
5. 在測試裝置驗證登入、區域、巡檢、改善、紅牌、設定、離線外殼與快取更新。
6. 完成審查與核准後提交 Git，提交訊息清楚描述功能與版本。
7. 將核准變更推送至 `main`；Pages 工作流程會發布 `docs/`。
8. 確認 GitHub Pages 部署成功，再以無痕視窗開啟正式入口。
9. 抽查已安裝 PWA 的更新、清快取、待同步與至少一支主要流程。
10. 記錄發布時間、提交、版本、驗證人與回復點。

### 6.5 GitHub Pages 發布判定

| 檢查 | 通過訊號 | 失敗處理 |
|---|---|---|
| 工作流程 | `Pages Deploy` 的 build 與 deploy 成功 | 不宣告上線，查看失敗步驟 |
| 發布來源 | 工作流程上傳 `docs` | 確認 5S 檔案位於 `docs/5s/` |
| 入口 | 正式網址回傳新版 HTML | 檢查部署時間與瀏覽器快取 |
| 版本 | 登入頁、設定頁與資源查詢值一致 | 停止驗收，修正版本矩陣 |
| 離線外殼 | 安裝後斷網仍可開啟入口 | 查 Service Worker、外殼清單與圖示 |
| API | 核心資料可重新讀取 | 查後端網址、CORS、GAS 部署與資料庫 |

### 6.6 快取升版與使用者更新

Service Worker 安裝新版後會刪除不是目前快取名稱的舊快取。核心腳本採網路優先、失敗才讀本機；一般靜態資源採快取優先並背景更新；GAS 請求不由 Service Worker 快取。

1. 發布時必須更換快取版本與所有 `?v=` 值。
2. 請使用者保持在線，完全關閉後重新開啟 PWA。
3. 到設定確認顯示新版本，再按「清除快取並更新」。
4. 若仍顯示舊版，先確認待同步為 0，再關閉所有同站分頁並重新開啟。
5. 只有待同步為 0、單號已在中央資料庫回讀後，才可移除網站資料或重新安裝 PWA。

### 6.7 前端回復

1. 停止新變更與擴大發布，保存失敗畫面、版本、裝置與時間。
2. 判斷問題是 Pages 發布、程式、快取、後端或資料，而不是立即回退所有元件。
3. 以 Git 中已驗證的提交建立修復提交，不使用破壞歷史的強制重設。
4. 若回復舊程式，仍建議發布新的修補版本與新快取鍵，確保裝置能取得變更。
5. 重新執行唯讀驗收、正式入口、實機與離線外殼查核。
6. 記錄回復原因、影響範圍、資料是否需修復與後續預防措施。

| `updateRow`／`智慧5S_更新資料列` | 更新既有 `5S_` 資料列 | 是，改善與紅牌狀態更新 |
| `智慧5S_健康檢查` | 查版本、資料庫與缺少分頁 | 管理員使用 |
| `智慧5S_初始化` | 建立／修復十四張 `5S_` 分頁 | 管理員受控使用 |
| `智慧5S_取得戰情` | 回傳指定日期戰情摘要 | 後端能力；首頁主要自行計算 |
| `智慧5S_產生日統計` | 重建當日區域統計與排名 | 管理員或每日觸發器 |
| `智慧5S_發送待通知` | 以本模組權杖直接推播 | 唯一 Bot 架構下不作正式主要路徑 |
| `智慧5S_儲存照片` | 將資料網址照片存到 Drive | 已有能力，現行 PWA 尚未接線 |

現行 PWA 另沿用通用 API 的 `sheetData`、`appendRow` 與 `updateRow`。部署時主 `doGet`／`doPost` 必須能把 5S 動作交給 `智慧5S_嘗試處理動作_`，同時不可破壞既有 NEXUS OS、報工、排程與 LINE 路由。

### 7.3 Script Properties

| 屬性 | 所在專案 | 用途 | 安全規則 |
|---|---|---|---|
| `智慧製造_SPREADSHEET_ID` | 主 GAS | 指定唯一中央資料庫 | 可核對識別碼，不對外分享編輯權 |
| `智慧5S_照片資料夾_ID` | 主 GAS | Drive 照片資料夾快取 | 只有接用 Drive 儲存功能後才會建立／使用 |
| `LINE_CHANNEL_ACCESS_TOKEN` | 既有 LINE GAS | 唯一 Bot 發送權杖 | 只確認已設定，不讀值、不複製 |

### 7.4 GAS 部署程序

1. 取得最新核准的 `智慧5S管理平台_完整後端.gs` 與主路由版本。
2. 在正式 Apps Script 專案建立版本前，保存目前可用部署版本與程式快照。
3. 比對專案識別碼、中央資料庫識別碼與 Web App 部署，確認沒有進入個人複本。
4. 更新 5S 模組與主路由接線，不覆蓋其他模組或改變既有動作順序。
5. 執行語法檢查、`智慧5S_健康檢查_()` 與 `測試_智慧5S管理平台完整後端()`。
6. 建立新的 Apps Script 版本並更新原 Web App 部署，不建立第二個正式網址。
7. 確認 Web App 仍以部署者身分執行、正式存取設定沒有非預期改變。
8. 跑正式唯讀驗收，確認十五張分頁、登入解析與版本一致。
9. 只有核准的驗收需要才執行正式寫入閉環，並保留驗收批次與封存狀態。
10. 記錄部署版本、時間、執行人、Git 提交、健康結果與回復版本。

### 7.5 健康檢查判讀

| 回傳欄位 | 正常 | 異常處理 |
|---|---|---|
| 成功 | `true` | 查看缺少分頁與資料庫是否正確 |
| 版本 | 與 PWA、LINE、文件一致 | 停止發布並校正版本矩陣 |
| 資料庫名稱 | `⭐智慧工廠主資料庫` | 檢查 Script Property 與預設識別碼 |
| 資料庫識別碼 | 正式識別碼 | 禁止在錯誤資料庫執行初始化或寫入 |
| 缺少分頁 | 空陣列 | 先備份，再判定建立或復原 |
| 訊息 | 智慧 5S 後端正常 | 保留執行結果作為部署證據 |

### 7.6 觸發器管理

後端提供 `智慧5S_建立每日觸發器_()`，會同時建立每日 17 時 10 分的統計與每小時直接通知。正式第 1.0.2 版採既有唯一 LINE Bot 橋接，因此不得未經架構審查就執行此合併函式，以免出現第二條通知路徑。

| 自動化 | 正式建議位置 | 處理函式 | 管理原則 |
|---|---|---|---|
| 每日區域統計 | 主 GAS | `智慧5S_每日自動化` | 可建立每日時間觸發器，時區台北 |
| 5S LINE 通知 | 既有 NEXUS OS LINE GAS | `智慧5S_LINE橋接_每小時` | 群組確認後才建立，每小時最多處理 30 筆 |
| 主 GAS 直接通知 | 主 GAS | `智慧5S_發送待通知自動化` | 唯一 Bot 正式架構下保持停用 |

## 八、唯一 LINE Bot 與通知管理

### 8.1 正式原則

智慧 5S 不建立第二個 LINE Bot、不複製 Channel Access Token、不建立第二張通知表。重大巡檢異常與新紅牌由 PWA 寫入唯一中央資料庫的 `5S_通知紀錄`，再由既有 NEXUS OS Apps Script 專案中的橋接模組送出。

### 8.2 通知欄位

| 欄位 | 用途 | 管理注意 |
|---|---|---|
| 通知編號 | 每筆通知追溯鍵 | 不重複使用 |
| 通知場景 | 重大巡檢異常或新紅牌等 | 與內容及來源一致 |
| 對象類型 | 區域群組等 | 不等於實際識別碼 |
| 對象識別碼 | LINE 收件群組或使用者 | 空白時橋接改為待設定，不送出 |
| 訊息類型 | 文字等 | 與橋接支援格式一致 |
| 內容摘要 | 實際推播內容 | 不得含不必要個資或祕密 |
| 狀態 | 待發送、已發送、待設定或失敗 | 只有待發送會被橋接自動處理 |
| 送出時間 | 成功發送時間 | 判斷是否可能重送的重要證據 |
| 錯誤訊息 | 缺設定或發送錯誤 | 修復前先保留原文 |
| 去重鍵 | 來源的業務去重資訊 | 橋接目前不會主動以此欄阻止重送 |

### 8.3 群組識別碼啟用

1. 由區域主管與 LINE 管理員共同確認正式 5S 收件群組。
2. 確認 Bot 已在該群組，且通知內容與接收對象符合個資及作業需求。
3. 取得群組識別碼後，以雙人核對填入 `5S_區域主檔.LINE群組識別碼`。
4. 不得推定既有檢具、報工或其他群組就是 5S 正式群組。
5. 執行 `智慧5S_LINE橋接_健康檢查()`，確認啟用區域數與已設定群組區域數。
6. 先以一個核准區域建立受控測試通知，確認只有正確群組收到。
7. 測試通過後執行 `智慧5S_LINE橋接_建立每小時觸發器()`。
8. 記錄群組、區域、核准人、測試通知編號、收件時間與觸發器建立者。

### 8.4 健康檢查最低條件

| 條件 | 正常 | 不正常時 |
|---|---|---|
| 既有 Bot 權杖已設定 | `true` | 由 LINE 管理員在 Script Properties 修復，不複製權杖 |
| 既有 `發送LINE通知()` 可用 | `true` | 檢查 NEXUS OS 主程式與函式名稱 |
| 中央通知分頁可用 | `true` | 核對資料庫識別碼、分頁與表頭 |
| 啟用區域數 | 與區域主檔一致 | 查 `啟用` 欄與空白列 |
| 已設定群組區域數 | 與已核准群組一致 | 不為追求通過而填入未知識別碼 |

### 8.5 狀態處理

| 原狀態 | 代表意義 | 下一步 |
|---|---|---|
| 待發送 | 等待橋接處理 | 由排程或核准的手動執行處理 |
| 已發送 | 發送函式完成並寫入送出時間 | 抽查正確群組收件，不再重送 |
| 待設定 | 缺少對象識別碼 | 補正區域群組後，依重送程序處理 |
| 失敗 | 內容空白或發送函式拋錯 | 保留錯誤、修正根因後依重送程序處理 |

### 8.6 安全重送

橋接只會處理狀態為「待發送」的資料；「待設定」與「失敗」不會自動重試。將狀態改回待發送前，必須避免同一通知被再次送出。

1. 依通知編號確認來源案件、對象、內容、送出時間與錯誤訊息。
2. 到目標群組確認是否實際收到；函式錯誤不一定代表收件端完全沒有訊息。
3. 修正群組識別碼、內容或 Bot 函式根因。
4. 由核准資料管理員記錄原狀態、修正原因與執行人。
5. 只有確認未送達時，才把該筆狀態改回「待發送」並清除過期錯誤；不改通知編號與去重鍵。
6. 手動執行小上限處理或等待下一次排程。
7. 確認狀態為已發送、送出時間已填且正確群組只收到一次。

### 8.7 暫停通知

1. 發現誤發、錯群組、異常大量通知或機密外洩風險時，先停用 `智慧5S_LINE橋接_每小時` 觸發器。
2. 保留待發送資料與錯誤證據，不批次改成已發送。
3. 盤點受影響通知編號、區域、收件群組與時間。
4. 修正主檔或程式後執行健康檢查與單筆受控測試。
5. 經 LINE 管理員與業務主管核准後恢復觸發器。

## 九、離線同步、快取與裝置管理

### 9.1 本機資料種類

| 儲存位置 | 內容 | 清除風險 |
|---|---|---|
| Local Storage | 目前使用者、裝置識別碼、各分頁讀取快取、可選後端權杖鍵 | 使用者需重登，離線讀取可能失去備援 |
| IndexedDB | `智慧5S本機資料庫` 的 `待同步佇列` | 未同步工作會永久遺失 |
| Cache Storage | PWA 應用程式外殼與已快取靜態資源 | 離線入口失效，需在線重新安裝 |
| Service Worker | 離線控制與快取版本 | 舊版控制可能持續到重新載入 |

### 9.2 補送機制

1. 新增或更新先嘗試送到正式 GAS。
2. 只有離線、逾時或常見網路抓取錯誤才會加入待同步；後端業務錯誤會直接顯示，不一定排隊。
3. 每筆工作保存本機識別碼、建立時間、工作類型、分頁、欄位、值、嘗試次數與最後錯誤。
4. 恢復在線、重新進入系統或按「立即同步」時，系統依建立時間逐筆補送。
5. 成功工作立即從佇列刪除；失敗工作保留並增加嘗試次數。
6. 一批資料可能部分成功、部分保留。不可因畫面仍有剩餘就重新填寫整張巡檢或盤點。

### 9.3 待同步不歸零

| 症狀 | 查核 | 處理 |
|---|---|---|
| 顯示離線 | 裝置網路與頁首狀態 | 連上穩定網路後再同步 |
| 成功部分、失敗部分 | 同步結果的成功、失敗、剩餘 | 不重送已成功部分，查後端錯誤 |
| 更新工作一直失敗 | 原資料列是否仍存在、列號是否過期 | 先查主鍵與中央列，不盲目重試 |
| 分頁不存在 | 健康檢查與正式資料庫 | 暫停裝置，修復分頁後再補送 |
| 欄位不一致 | 正式表頭與工作欄位 | 評估版本差異，必要時做授權轉換 |
| 長時間逾時 | GAS 執行量、網路與 Web App | 降低同時補送裝置數，查執行紀錄 |

### 9.4 裝置救援原則

1. 不登出、不清網站資料、不解除安裝，先保持裝置電力與瀏覽器資料。
2. 記錄使用者、裝置識別碼、待同步筆數、作業時間、區域與已顯示單號。
3. 以另一裝置查中央資料庫，判斷哪些工作已成功寫入。
4. 先修復網路、GAS、分頁或欄位根因，再在原裝置按一次立即同步。
5. 若仍失敗，由系統管理員在瀏覽器開發工具只讀檢查 IndexedDB 工作內容；未備份前不刪資料表。
6. 需要人工補登時，依每筆主鍵與原始值做授權資料修正，禁止重做整張流程造成重複。
7. 中央回讀完整且待同步為 0 後，才可重設裝置。

### 9.5 重複資料判定

| 判定線索 | 用途 |
|---|---|
| 業務單號 | 巡檢、明細、改善、盤點、紅牌與照片的第一比對鍵 |
| 建立時間 | 判斷是否由同一次離線作業產生 |
| 裝置識別碼 | 找出來源裝置 |
| 使用者工號 | 確認操作身分 |
| 區域與內容 | 排除不同作業恰好相近 |
| 待同步與中央回讀 | 判斷工作是否已成功但畫面尚未更新 |

### 9.6 快取異常處理順序

1. 確認正式入口與線上版本已發布成功。
2. 到設定確認待同步為 0。
3. 按「清除快取並更新」，這只清除 PWA 的分頁資料快取，不清 IndexedDB 佇列。
4. 完全關閉並重新開啟 PWA，核對版本。
5. 仍異常時，以無痕視窗確認是否為裝置快取而非正式服務問題。
6. 最後才在待同步為 0 且中央資料已回讀後，移除網站資料或重新安裝。

## 十、照片、容量與個資管理

### 10.1 現行照片模式

PWA 會在裝置端把照片縮小並調整品質，直到資料網址不超過約 42,000 字元，再寫入巡檢明細、改善、盤點或 `5S_照片`。因此中央試算表容量、載入速度與備份大小都會隨照片增加。

### 10.2 Drive 儲存能力邊界

GAS 已提供 `智慧5S_儲存照片_()`，可接受 JPEG、JPG、PNG 或 WebP 的資料網址，建立或重用 `智慧5S照片資料庫` Drive 資料夾，並回傳檔案識別碼、縮圖與 Drive 網址。但第 1.0.2 版 PWA 尚未改為呼叫此動作，不能把函式存在當成正式照片已外部化。

### 10.3 照片容量監控

| 項目 | 建議查核 | 異常訊號 |
|---|---|---|
| `5S_照片` 列數 | 每週新增量與累計量 | 短期異常暴增或重複單號 |
| 試算表開啟與 API 讀取 | 載入時間、逾時與錯誤 | 接近請求逾時、手機載入明顯變慢 |
| 單筆照片資料 | 是否低於前端上限 | 大量接近上限或不符合圖片格式 |
| 重複照片 | 同單號、時間、摘要與內容 | 離線補送或重做流程造成重複 |
| Drive 資料夾 | 只在正式接線後監控 | 孤兒檔案、權限過寬、縮圖失效 |

### 10.4 照片外部化變更條件

1. 先定義哪些交易欄位保存網址、哪些保留摘要與原圖保存期限。
2. 建立測試資料庫與測試 Drive 資料夾，不在正式資料上直接遷移。
3. 修改 PWA 上傳、離線排隊、回讀顯示與錯誤復原流程。
4. 驗證 Drive 權限不會讓非授權人員瀏覽全部照片。
5. 驗證離線工作補送時不會重複建立檔案或留下孤兒檔案。
6. 完成既有照片遷移、回復與連結有效性方案。
7. 經資安、業務與系統核准後，與前端、GAS、資料表及文件一起升版。

### 10.5 個資與機密

- 不拍攝無關人臉、工號名單、薪資、醫療、密碼、客戶機密、電腦螢幕或受限圖面。
- 異常照片以定位問題所需範圍為限；可避免的人員影像應避開。
- 不把照片資料、縮圖連結或 Drive 網址貼到公開 Issue、公開文件或個人通訊群組。
- 發現誤拍敏感資料時，立即限制存取、保留事件證據並依核准程序處理，不自行刪除所有關聯。

## 十一、監控、例行維護與驗收

### 11.1 每日檢查

1. 開啟正式 PWA，核對版本、連線與核心資料載入。
2. 查 Apps Script 執行紀錄，確認沒有持續例外、配額或權限錯誤。
3. 確認 `5S_通知紀錄` 沒有異常堆積的待發送、待設定或失敗。
4. 確認 `5S_區域日統計` 與 `5S_排名快照` 已更新到當日，或依排程時點判斷尚未到執行時間。
5. 抽查一筆今日巡檢、改善狀態或紅牌，確認 PWA 與中央資料一致。
6. 收班前確認公用裝置的待同步已歸零或已完成具名交接。

### 11.2 每週檢查

- [ ] 十五張必要分頁存在，表頭順序與正式規格一致。
- [ ] 區域主檔沒有重複代碼、失效責任人或未核准群組識別碼。

## 十三、故障診斷與事件處理

### 13.1 先分類再處理

| 類別 | 典型現象 | 第一查核點 |

| 入口／Pages | 404、白畫面、舊版 | Pages 工作流程、正式路徑與瀏覽器快取 |
| PWA 程式 | 按鈕無反應、畫面錯誤 | 瀏覽器主控台、JavaScript 語法與版本 |
| GAS／API | 逾時、未知動作、回傳格式錯誤 | Web App 部署、路由、執行紀錄 |
| 資料庫 | 找不到分頁、欄位或資料 | 正式識別碼、分頁表頭、權限 |
| 身分／角色 | 找不到人、角色錯誤 | `01_人員主檔` 與本機登入快取 |
| 離線同步 | 待同步不降、重複資料 | IndexedDB 工作、中央回讀、列號 |
| LINE | 待設定、失敗、錯群組、重複 | 區域群組、通知狀態、觸發器與收件證據 |
| 統計 | 今日資料未更新、排名錯誤 | 時區、來源資料、統計觸發器 |
| 照片 | 過大、無法顯示、容量慢 | 壓縮上限、資料格式與欄位內容 |

### 13.2 登入找不到工號或姓名

1. 以完整工號查 `01_人員主檔`，確認沒有前後空白、數字格式或重複列。
2. 核對表頭含 `工號`、`姓名`，資料回傳不是包在未支援的格式。
3. 使用正式 API 的 `sheetData` 讀取一筆人員資料。
4. 執行唯讀驗收的人員解析項目。
5. 確認 `智慧5S資料修復.js` 已由 `index.html` 在主應用程式前載入。
6. 在線按「清除快取並更新」後再用完整工號登入。

診斷路徑固定為：`GAS → sheetData → 01_人員主檔 → headers／rows → 智慧5S資料修復 → 登入解析`。

### 13.3 看不到區域或檢查項目

| 現象 | 可能原因 | 修復 |
|---|---|---|
| 全部區域不見 | 核心資料載入失敗、分頁名稱錯誤 | 查 API、健康檢查與 `5S_區域主檔` |
| 單一區域不見 | `啟用` 為否或快取尚未更新 | 核對主檔，清除分頁快取 |
| 區域可見但無項目 | 清單代碼不一致或項目全停用 | 比對完整清單代碼與啟用欄 |
| 項目順序錯 | 順序值空白、非數字或重複 | 修正主檔並重新驗收 |
| 5S 分類統計分散 | 類別文字不一致 | 統一為五個受控分類 |

### 13.4 改善或紅牌更新失敗

1. 確認畫面資料包含 `_列號`；缺少時重新讀取，不直接填列號。
2. 核對 Web App 已部署含 `updateRow` 的正式版本 16。
3. 查分頁名稱是否以 `5S_` 開頭且列仍存在。
4. 以主鍵搜尋中央資料，避免快取列號指到別筆資料。
5. 查 Apps Script Lock、執行逾時與表頭欄名。
6. 如果部分流程已成功，按改善歷程與中央狀態修復，不重新執行整個操作。

### 13.5 LINE 未收到

1. 以通知編號查 `5S_通知紀錄`。
2. 若仍待發送，查觸發器最近執行與 Apps Script 錯誤。
3. 若待設定，查對象識別碼與區域主檔群組。
4. 若失敗，保留完整錯誤，查權杖存在性與 `發送LINE通知()`。
5. 若已發送，核對送出時間、目標識別碼與群組實際收件；不要直接重送。
6. 修復後依安全重送程序處理，確認只收到一次。

### 13.6 今日統計未更新

1. 確認目前時間是否已超過每日排程時點。
2. 查主 GAS 是否存在 `智慧5S_每日自動化` 觸發器及最近執行。
3. 核對 Apps Script 時區為台北。
4. 查當日巡檢日期格式、區域代碼與作廢狀態。
5. 在來源正確後手動執行一次日統計，核對回傳區域數。
6. 若統計仍錯，停止手改結果，逐區重算來源資料。

### 13.7 照片錯誤

| 訊息／現象 | 原因 | 處理 |
|---|---|---|
| 照片仍過大 | 壓縮後仍超過 42,000 字元 | 靠近拍攝、降低相機解析度後重拍 |
| 照片資料格式不正確 | Drive 儲存動作收到非支援資料網址 | 查 MIME 與 Base64 前綴 |
| 圖片無法顯示 | 資料截斷、網址權限或格式錯誤 | 保留原單號，查照片列與來源欄位 |
| 載入很慢 | 試算表照片資料量增長 | 做容量盤點，評估受控外部化 |

### 13.8 事件嚴重度

| 等級 | 條件 | 立即動作 |
|---|---|---|
| 第一級 | 敏感資料外洩、錯資料庫大量寫入、資料錯位、錯群組大量推播 | 立即停止寫入／通知，通知最高主管與資安責任人 |

| 第三級 | 單一功能、區域、裝置或通知失敗 | 保留證據、設定時限修復與回歸 |
| 第四級 | 顯示、文件或非關鍵改善建議 | 納入受控變更，不直接改正式版 |

## 十五、資安與資料治理強化

### 15.1 現行風險認知

第 1.0.2 版 PWA 以人員主檔資料與本機快取提供登入體驗，管理按鈕由前端角色判定；Web App 允許匿名存取並以部署者身分執行。這種設計便於現場使用，但不等同密碼、單一登入或服務端角色授權。管理員必須把它列為正式風險，不得用「畫面看不到按鈕」推定 API 已完全阻擋未授權請求。

### 15.2 立即控制

- 只開放必要 API 動作與必要分頁，維持 `updateRow` 只限 `5S_` 分頁。
- 不讓一般使用者取得試算表或 Apps Script 編輯權。
- 以唯一正式入口、版本與部署降低假入口及錯後端風險。
- 定期檢查 Git、Issue、文件與試算表是否出現權杖或敏感資料。
- 監控 Apps Script 執行、異常寫入、重複主鍵與非預期大量請求。
- 重要管理動作要求現場證據、歷程與主管核准，不只依賴按鈕可見性。

### 15.3 後續強化順序

1. 在服務端建立可驗證的使用者工作階段或簽章權杖，不只接收本機任意字串。
2. 由服務端依使用者與動作檢查主管、區域負責人或資料管理權限。
3. 對 `appendRow` 與 `updateRow` 建立允許分頁、允許欄位、狀態轉移與資料驗證。
4. 建立請求識別碼與業務去重，避免重試造成重複交易或通知。
5. 對敏感資料、照片與操作紀錄訂定保存、存取與刪除規則。
6. 以測試環境驗證後再升版，不在第 1.0.2 版正式資料上直接試驗。

## 十七、系統管理員快速操作卡

### 17.1 每日五分鐘

1. 正式入口核對版本與登入。
2. Apps Script 查無持續失敗。
3. 通知查無異常待發送、待設定或失敗。
4. 日統計與排名依排程更新。
5. 公用裝置待同步為 0 或具名交接。

### 17.2 發布前十項

- [ ] 變更單與核准完整。
- [ ] 唯一入口、資料庫與 LINE Bot 未改變。
- [ ] Git、GAS 與試算表備份可回復。
- [ ] 版本與 `v=`、快取鍵全部一致。
- [ ] 不含權杖、祕密、正式個資與測試殘留。
- [ ] 唯讀驗收全部通過。
- [ ] 高風險變更已完成測試寫入與實機驗收。
- [ ] 其他主線回歸正常。
- [ ] 發布與回復負責人已確認。
- [ ] 文件與實際系統同步。

### 17.3 故障時八步

1. 停止擴大影響，不連續重試。
2. 保存畫面、錯誤、單號、版本、裝置與時間。
3. 判斷入口、前端、GAS、資料、離線、LINE 或統計類別。
4. 備份現況與關聯資料。
5. 修正根因，不只改表面狀態。
6. 唯讀驗收後做最小受控測試。
7. 分批恢復寫入、同步與通知。
8. 完成事件、修正與防再發紀錄。

### 17.4 不可跨越的停止條件

| 發現 | 立即停止 |
|---|---|
| 資料庫名稱或識別碼不符 | 所有初始化、寫入與修正 |
| 備份無法開啟或無回復點 | 正式資料與程式變更 |
| 待同步裝置仍有未確認工作 | 清網站資料、重裝與資料列復原 |
| LINE 群組未由管理者確認 | 觸發器建立與實際推播 |
| 版本矩陣不一致 | `main` 發布與 GAS 升版 |
| 唯讀驗收失敗 | 正式寫入驗收與上線宣告 |
| 權杖或敏感資料出現在原始碼 | 提交、推送與文件發行 |
