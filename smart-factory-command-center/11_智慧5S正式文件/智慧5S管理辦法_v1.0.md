## 第一章　總則

### 第一條（目的）

為建立化新精密現場「整理、整頓、清掃、清潔、素養」的一致管理標準，透過數位巡檢、照片證據、異常改善、紅牌處置、驗證結案及績效複盤，使 5S 由單次整理活動轉為可追溯、可複製與可持續的日常管理制度，特制定本辦法。

### 第二條（系統與制度關係）

本辦法以「化新精密｜智慧 5S 管理平台」為正式執行工具，系統由 PWA、Google Apps Script、智慧工廠主資料庫、既有唯一 LINE Bot 與 GitHub 組成。本辦法不取代既有安全、品質、設備、資產或環安衛規範；如規定衝突，應先依較嚴格的公司規範執行。

### 第三條（適用範圍）

本辦法適用於已納入智慧 5S 的生產區、工作台、檢驗桌、通道、工具、文件、物品暫存區及其他核准區域。第一階段範圍為：

- A9 簡單專線示範區。
- A9 1069 檢驗桌。
- A9 1070 檢驗桌。
- A9 紅牌暫存區。

後續區域須完成責任人、基準照片、檢查項目、巡檢頻率與實機驗收後，方可正式納入。

### 第四條（管理原則）

1. 必要性優先：先判定是否需要，再決定保留、定位或處置。
2. 使用頻率分層：每日使用物置於伸手可及處；每週、每月及少用物逐層外移。
3. 一物一位：名稱、位置、數量上限與責任人須可辨識。
4. 目視可判定：應能透過基準照片、定位線、標籤及容量上限快速判斷。
5. 異常必閉環：不符合項目必須有原因、照片、責任、期限與驗證。
6. 數據只留一份：正式紀錄回寫中央主資料庫，不另建平行帳本。
7. 證據優於口頭：會議或口頭回報不得取代系統紀錄。
8. 數據用於改善：KPI 用於找出重複問題與資源需求，不以單一分數直接懲處個人。

## 第二章　名詞與判定標準

### 第五條（5S 定義）

| 類別 | 管理定義 | 現場判定重點 |
|---|---|---|
| 整理 | 區分必要、非必要與待判定物品 | 使用頻率、最近使用日、保留上限、紅牌需求 |
| 整頓 | 讓必要物品有固定位置並可迅速取用、復原 | 一物一位、定位線、標籤、數量上限 |
| 清掃 | 移除汙染並在清掃中發現異常 | 油污、切屑、粉塵、漏液、破損、工具狀況 |
| 清潔 | 將前三項轉為可重複執行的標準 | 基準照片、檢查清單、頻率、責任與異常處理 |
| 素養 | 按標準執行、使用後復原並主動通報 | 班前復原、交接、不符合回報、持續改善 |

### 第六條（作業名詞）

- 基準照片：經區域負責人與主管確認，作為現場合格狀態的影像標準。
- 行動巡檢：使用智慧 5S PWA 逐項判定、記錄與送出的正式巡查。
- 改善單：巡檢項目低於 5 分或紅牌案件產生的責任追蹤紀錄。
- 驗證：由主管或區域負責人檢查改善後現況、照片與持續性，決定通過或駁回。
- 紅牌：對非必要或待處置物品建立的辨識、暫存、會辦與結案機制。
- 正式資料：由受控帳號經 PWA 與正式 API 寫入中央主資料庫的紀錄。

## 第三章　組織、責任與權限

### 第七條（組織責任）

| 角色 | 主要責任 | 權限邊界 |
|---|---|---|
| 推動核准主管 | 核准制度、階段範圍、重大資源與展開門檻 | 處理重大議題與跨部門障礙 |
| 推動主責人 | 維護計畫、進度、文件版本、會議與展開清單 | 不代替區域主管做結案判定 |
| 區域主管 | 指定責任人、審查標準、週抽查、驗證重大改善 | 可駁回不完整或無效改善 |
| 區域負責人 | 維護基準、安排巡檢、追蹤復原、改善及紅牌 | 管理所屬區域，不得擅自變更跨區標準 |
| 現場人員 | 班前與交接復原、巡檢、拍照、回報與改善 | 只能操作本人或所屬區域案件 |
| 種子教官 | 交叉判定、教學、同組複製與常見錯誤糾正 | 教學不取代主管驗證 |
| 系統管理員 | 維護主檔、參數、權限、觸發器、版本、備份與異常修復 | 不得代替現場主管判定合格 |
| LINE 群組管理者 | 確認正式收件群組、識別碼與誤發停用 | 未雙人確認前不得啟用自動推播 |

### 第八條（系統角色判定）

人員以既有 `01_人員主檔` 的工號或姓名登入。系統依職稱與角色類型判定「主管」、「區域負責人」或「現場人員」。人員停用、異動、部門、組別或職稱變更時，應先更新人員主檔，不得為 5S 另建重複帳號。

### 第九條（驗證與結案權限）

- 改善執行人不得自行宣告結案。
- 改善單由主管或區域負責人驗證；重大異常優先由區域主管驗證。
- 紅牌只能在處置證據、實際處置日及複查人完整後結案。
- 系統管理員只能處理資料錯列、同步或技術異常，不得擅自將現場案件改為已結案。

## 第四章　區域、基準與復原

### 第十條（區域主檔）

每一正式區域應在 `5S_區域主檔` 建立唯一區域代碼、區域名稱、所屬部門、區域負責人工號、檢查清單代碼與 LINE 群組識別碼。缺少責任人或檢查清單時，不得列為正式週期巡檢區域。

### 第十一條（基準建立）

區域負責人應與種子教官共同建立：

1. 區域邊界與平面範圍。
2. 文件、量檢具、樣品、治具、清潔工具及飲料容器的必要性判定。
3. 定位線、名稱、數量上限、有效期與責任標示。
4. 合格基準照片與必要視角。
5. 巡檢項目、權重、頻率、異常範例與復原方式。

基準須由區域主管核准。平面、設備、產品或作業方法變更後，應在下一次正式巡檢前完成基準複核。

### 第十二條（每日自主復原）

現場人員於班前、交接或作業結束時，應依基準照片確認通道、桌面、工具、文件、清潔用品及待處理物品。可當班立即排除的小問題先完成復原；無法當班排除、涉及安全、品質或跨部門的問題，必須建立改善單。

## 第五章　巡檢與評分

### 第十三條（巡檢頻率）

| 執行對象 | 最低頻率 | 主要作業 | 正式輸出 |
|---|---|---|---|
| 現場人員 | 每班／每日 | 自主復原、當日異常回報 | 必要時建立巡檢或改善證據 |
| 區域負責人 | 每日 | 區域狀態、未結改善、紅牌與復原確認 | PWA 巡檢、改善追蹤 |
| 區域主管 | 每週 | 抽查判定一致性、逾期與重大異常 | 週檢討紀錄、驗證結果 |
| 種子教官 | 每週／展開前 | 交叉判定、教學與常見錯誤糾正 | 教學紀錄、差異清單 |
| 推動主責人 | 每月 | KPI、重複異常、跨區域問題與展開門檻 | 月度管理複盤 |

### 第十四條（巡檢執行）

1. 使用人應以本人工號或姓名登入，選擇正確區域。
2. 依 `5S_檢查項目` 逐項判定，不得跳過未評項目。
3. 低於 5 分的項目必須填寫異常原因；系統要求時必須拍攝異常照片。
4. 重大異常不得為了完成巡檢而延後安全隔離、停機或主管通報。
5. 巡檢送出後不得直接覆寫原判定；後續處理須進入改善歷程。

### 第十五條（評分標準）

| 分數 | 判定 | 系統嚴重度 | 執行要求 | 系統結果 |
|---|---|---|---|---|
| 5 | 符合 | 無 | 完全符合已核准標準 | 保留巡檢紀錄 |
| 3 | 輕微偏差 | 低 | 需填原因並完成復原或改善 | 自動建立改善單 |
| 1 | 異常 | 中 | 需照片、責任人與期限 | 自動建立改善單 |
| 0 | 重大異常 | 高 | 立即控制風險並通報主管 | 自動建立改善單與待通知紀錄 |

巡檢得分率以「總得分／最高總分」計算。正式系統警示門檻為 85 分；得分達 85 分不代表個別異常可不改善，任一單項低於 5 分仍必須完成閉環。

### 第十六條（照片證據）

照片應拍攝能識別區域、物品、異常位置與改善結果的視角。改善前後照片應儘量使用相同方向與距離。不得上傳與 5S 判定無關的個人敏感資料、證件、薪資、醫療或私人通訊畫面。

## 第六章　異常改善與驗證

### 第十七條（改善單建立）

任一巡檢項目低於 5 分時，系統自動建立 `5S_改善單` 與 `5S_改善歷程`。改善單應至少包含來源單號、區域、5S 分類、問題說明、嚴重度、負責人、期限、狀態、前後照片、驗證人及驗證結果。

### 第十八條（改善期限）

改善單正式預設期限為建立日起 7 日。如為 0 分重大異常，負責人應於當班先完成風險隔離、標示、停用或臨時控制，不得以 7 日期限為由延後即時控制。因採購、工程、資產會辦或其他客觀原因需延長時，應在到期前由區域主管記錄原因、新期限與臨時對策。

### 第十九條（改善狀態）

| 狀態 | 說明 | 責任動作 |
|---|---|---|
| 待改善 | 案件已建立，尚未開始 | 負責人確認問題、期限與控制要求 |
| 改善中 | 已開始處理或驗證駁回 | 完成實際改善、拍攝改善後照片並填寫說明 |
| 驗證中 | 執行人已完成並送驗 | 主管或區域負責人檢查證據與現況 |
| 已結案 | 驗證通過並留下結案時間 | 案件唯讀保留，後續再發應建立新案件 |

驗證駁回時，系統將案件回到「改善中」，並於驗證結果與改善歷程留下駁回原因。

### 第二十條（改善驗證）

驗證應同時檢查：

- 問題是否真正排除，而非只為拍照短暫整理。
- 改善後照片、處置說明與現場結果是否一致。
- 定位、標籤、數量上限、責任或基準是否已補強。
- 是否需跨部門、採購、工程、資產或環安衛進一步處理。
- 相同異常是否重複發生，必要時調整檢查清單或進行水平展開。

### 第二十一條（逾期管理）

系統依期限計算逾期天數。區域負責人應每週檢視未結案與逾期案件；逾期時應當日回覆原因、臨時對策與預定完成日。重大或重複逾期案件應納入主管會議追蹤。

## 第七章　全物品盤點與紅牌管理

### 第二十二條（物品盤點）

現場物品應依每日、每週、每月、很少使用或用不到進行頻率分層，並記錄名稱、位置、規格、數量、使用頻率、必要性判定、保留上限、責任部門與建議處置。

### 第二十三條（紅牌建立）

物品判定為「非必要」時，必須填寫判定理由並拍照。系統應同時建立全物品盤點紀錄、紅牌追蹤、連動改善單、改善歷程及待通知紀錄。判定為「待判定」時，應指定確認人與確認日期，不得無限期留在原位置。

### 第二十四條（紅牌暫存與期限）

非必要品應移至核准的紅牌暫存區；第一階段預設暫存位置為「A9 紅牌暫存區」。紅牌預設處置期限為掛牌日起 30 日。暫存品應標示紅牌編號、物品名稱、數量、責任部門、預定處置日與建議處置。

### 第二十五條（處置與結案）

紅牌狀態為「待處置 → 處理中 → 已結案」。處置方式可包含移轉、退庫、返還保管單位、核准保留、報廢、回收或其他核准方式。涉及固定資產、客戶資產、檢量具、化學品、環安衛或財務帳務時，必須完成原規定的會辦與核准，不得因掛紅牌而直接報廢。

紅牌結案必須留下實際處置日、處置結果證據與複查人，並連動更新改善單。

## 第八章　數位紀錄與資料治理

### 第二十六條（正式資料來源）

智慧工廠主資料庫為唯一正式資料來源。人員登入引用 `01_人員主檔`；5S 正式資料由下列受控分頁組成：

| 資料類型 | 受控分頁 | 主要用途 |
|---|---|---|
| 主檔與參數 | `5S_區域主檔`、`5S_檢查項目`、`5S_系統參數` | 區域、清單、期限、及格門檻與版本 |
| 巡檢證據 | `5S_巡檢主檔`、`5S_巡檢明細`、`5S_照片` | 巡檢結果、單項評分、原因與照片 |
| 改善閉環 | `5S_改善單`、`5S_改善歷程` | 責任、期限、狀態、驗證與結案 |
| 紅牌處置 | `5S_全物品盤點`、`5S_紅牌追蹤`、`5S_非必要品處置` | 必要性、暫存、會辦、處置與複查 |
| 通知與績效 | `5S_通知紀錄`、`5S_區域日統計`、`5S_排名快照` | 推播軌跡、KPI、趨勢與區域比較 |

### 第二十七條（資料寫入與修正）

- 正式巡檢、改善、紅牌及處置資料應由 PWA 經正式 GAS API 寫入。
- 不得以人工新增列、搬移列或更改欄位順序的方式處理一般業務。
- 系統管理員因資料錯列、同步異常或修復需求而調整資料時，必須保留原值、新值、修正原因、執行人與時間。
- `updateRow` 只允許更新 `5S_` 分頁；不得將權限擴大至無關主檔或其他系統資料。

### 第二十八條（測試與正式資料分離）

系統驗收資料應使用 `SYSTEM-5S-TEST` 或「智慧5S自動驗收」等明確標記，不得納入正式績效。測試巡檢單可依驗收流程封存為「作廢」；已完成閉環驗證的改善、紅牌與處置紀錄依合法狀態保留為「已結案」，並由績效統計排除。

### 第二十九條（照片與容量管理）

目前正式版將手機照片壓縮後寫入中央資料庫，單張資料上限約 42,000 字元。上傳者應確認照片清晰且可辨識；資料保存年限依公司文件與資訊管理規範辦理。未完成保存年限核准前，正式紀錄不得任意刪除。

## 第九章　PWA、離線與裝置管理

### 第三十條（正式入口）

同仁應使用已公告的智慧 5S 正式 PWA 入口，不得使用不明書籤、舊版網址或個人副本執行正式巡檢。系統須保持 Manifest、Service Worker、離線頁與快取版本一致。

### 第三十一條（離線作業）

現場訊號不佳時，PWA 可啟動離線外殼並將待送資料存入 IndexedDB 佇列。操作人員應在網路恢復後確認補送成功，並於班別結束前檢查待同步筆數。系統應以業務主鍵與去重邏輯避免重複補送。

### 第三十二條（裝置與帳號）

- 公用手機、平板或電腦使用完畢後，應退出個人帳號或依班別交接。
- 不得借用他人工號巡檢、驗證或結案。
- 手機相機、儲存空間、日期時間與 PWA 版本應於正式啟用前完成檢查。
- 裝置遺失、帳號異常或資料無法同步時，應立即通知系統管理員。

## 第十章　LINE 通知與升級通報

### 第三十三條（唯一 LINE Bot）

智慧 5S 必須使用既有 NEXUS OS 唯一 LINE Bot 及既有發送函式，不得另建第二個 LINE Bot、第二個 Channel Access Token 或重複入口。權杖不得寫入前端、文件或 Git 儲存庫。

### 第三十四條（通知場景）

正式自動通知場景至少包含：

- 0 分重大巡檢異常。
- 新增紅牌。
- 後續核准的逾期、重複異常或重大升級場景。

系統先寫入 `5S_通知紀錄`，狀態為「待發送」，由既有 Bot 橋接發送後轉為「已發送」；缺少收件對象時標記「待設定」，發送異常時標記「發送失敗」並保留錯誤訊息。

### 第三十五條（啟用與防誤發）

各區域 LINE 群組識別碼必須由區域主管與 LINE 群組管理者雙人確認，並完成單筆測試後，才可建立每小時待通知處理觸發器。未確認前應保持不發送，不得以臨時或不明群組進行正式測試。

異常涉及人身安全、重大品質、停線或生產中斷時，應依現行緊急通報流程立即口頭或電話升級，不得只等待 LINE 自動推播。

## 第十一章　KPI、會議與持續改善

### 第三十六條（績效指標）

第一個月先建立基準值，再依實際難度、資源與穩定度核准目標。基本 KPI 包含：

| 指標 | 管理意義 | 檢視頻率 | 資料來源 |
|---|---|---|---|
| 巡檢完成率 | 應巡檢與已完成的差異 | 日／週 | 巡檢主檔 |
| 平均得分率 | 區域狀態與基準穩定性 | 週／月 | 巡檢主檔與明細 |
| 改善準時結案率 | 期限內完成改善與驗證的能力 | 週 | 改善單與歷程 |
| 逾期改善占比 | 資源或責任阻塞程度 | 日／週 | 改善單 |
| 重複異常率 | 是否只治標未治本 | 月 | 巡檢明細與改善單 |
| 紅牌準時處置率 | 非必要品處置效率 | 週／月 | 紅牌追蹤 |
| 資料同步成功率 | 離線補送、錯列與系統可靠度 | 週 | 通知與系統紀錄 |

### 第三十七條（管理複盤）

- 每週：已巡與未巡區域、新增異常、未結改善、逾期、紅牌、重複問題與系統異常。
- 每月：KPI 趨勢、區域比較、重大改善、已消除風險、展開區域、訓練與資源需求。
- 重大異常：依安全、品質與生產影響立即處理，不得等待週會或月會。

### 第三十八條（分數與排名使用）

分數與排名用於檢視區域趨勢、經驗複製與改善資源分配。在基準、巡檢次數、檢查項目難度或班別條件尚未一致前，不得直接用於個人績效、獎懲或跨區排名。

## 第十二章　教育訓練、稽核與異常處理

### 第三十九條（教育訓練）

正式啟用前，應依角色完成 5S 判定、基準照片、登入、巡檢、拍照、離線補送、改善、驗證、紅牌及系統維運訓練。驗收應以現場實作為主，至少完成一張巡檢、一項異常改善或角色對應情境演練。

### 第四十條（內部稽核）

稽核應檢查現場與系統是否一致，並至少包含：

- 區域、責任人、基準照片與檢查項目是否有效。
- 巡檢是否完整，低於 5 分是否有原因與證據。
- 改善單是否有責任、期限、前後照片與獨立驗證。
- 紅牌實物、系統紀錄、暫存位置與處置證據是否一致。
- 離線佇列、資料錯列、權限、照片、LINE 通知與版本是否異常。

### 第四十一條（違反處理）

第一次或因不熟悉造成的錯誤，優先採一對一輔導、簡化欄位、現場實作與再訓練。如經輔導後仍故意不執行、虛假填寫、借用帳號、刪改證據、擅自結案或導致安全與品質風險時，由主管查證後依公司現行管理規章處理。系統紀錄只作為事實證據之一，不以自動分數直接懲處。

### 第四十二條（系統異常）

如發生無法登入、資料無法載入、待同步無法清空、照片失敗、錯列、重複補送、權限異常或 LINE 誤發，應停止重複操作，保留畫面、單號、時間、工號、裝置與網路狀態，交由系統管理員處理。未完成根因確認前，不得用人工補列掩蓋問題。

## 第十三章　文件、變更與附則

### 第四十三條（文件同步）

智慧 5S 系列文件包含推動計畫書、管理辦法、SOP、完整操作手冊、現場操作手冊、主管操作手冊、系統管理手冊、教育訓練教材、快速操作卡、A3 流程海報、ISO 文件、KPI 手冊、稽核手冊與會議簡報。系統功能、狀態字典、欄位、權限、期限或通知邏輯變更時，必須同步檢查相關文件。

### 第四十四條（變更管理）

系統與文件變更應使用 Git 保留提交、驗收與部署軌跡。正式系統版本不得低於文件所依據的已驗收版本。重大變更應先在驗收資料或指定測試區驗證，再更新正式入口與文件。

### 第四十五條（例外管理）

因安全、生產、設備、客戶或空間限制無法依原標準執行時，區域負責人應提出原因、替代控制、適用範圍與期限，經區域主管核准後執行。例外到期應重新檢視，不得自動延長。

### 第四十六條（生效與修訂）

本辦法經核准並公告後生效，修訂時亦同。未完成核准前，可用於 A9 示範區實機驗收與教育訓練，不得擴大為全廠個人獎懲依據。
