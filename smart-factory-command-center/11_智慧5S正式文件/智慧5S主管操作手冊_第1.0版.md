## 一、這本手冊怎麼用

### 1.1 使用目的

本手冊供主管與區域負責人執行智慧 5S 的每日管理、案件追蹤、改善驗證、紅牌結案、逾期升級與會議複盤。內容依正式畫面與目前權限編寫，重點不是只把數字結清，而是確保現場風險真的受控、改善真的恢復標準、資料真的可以追溯。

### 1.2 主管權限如何形成

系統會依人員主檔中的職稱與角色類型判定系統角色。經理、副理、課長、主任或主管類職稱通常顯示為「主管」；工程師、助理工程師、領班、組長或幹部類通常顯示為「區域負責人」。兩種管理角色目前都可執行改善驗證與紅牌結案。

| 設定頁顯示角色 | 可使用的管理動作 | 主要責任 | 不得執行 |
|---|---|---|---|
| 主管 | 查看全體戰情、驗證改善、駁回改善、完成紅牌結案 | 資源、優先順序、期限風險、最終判定 | 未到現場就結案、借用他人身分 |
| 區域負責人 | 追蹤區域案件、驗證改善、駁回改善、完成紅牌結案 | 區域基準、現場驗證、交接與處置 | 越權修改主檔、用口頭交辦代替紀錄 |
| 現場人員 | 巡檢、開始改善、完成並送驗、開始紅牌處理 | 依事實執行與留證 | 驗證自己的案件、代替主管結案 |

> 登入後先到「設定」核對姓名、工號、職稱與「系統角色」。應有管理權限卻只顯示「現場人員」時，停止驗證與結案，交由人員主檔授權流程修正。

### 1.3 六項管理原則

1. 先控制人身、安全、品質、設備與生產中斷風險，再補系統紀錄。
2. 主管判定以現場事實、前後照片、處理說明與標準為依據。
3. 「送驗」不是「結案」；只有管理角色驗證通過才算閉環。
4. 「移到別處」、「先擦掉」或「之後再處理」都不能直接結案。
5. 排名用來找趨勢與好做法，不直接作為個人獎懲依據。
6. 不自行刪資料、不直接修改試算表、不改日期掩蓋逾期。

### 1.4 開班六十秒檢查

- [ ] 首頁與設定頁顯示本人姓名及正確管理角色。
- [ ] 系統版本顯示第 1.0.2 版。
- [ ] 頁首連線狀態為「在線」。
- [ ] 設定頁「待同步」為 0。
- [ ] 首頁戰情已按「更新戰情」。
- [ ] 已掌握今日 0 分、高嚴重度、逾期改善與逾期紅牌。

## 二、主管戰情中心怎麼看

### 2.1 先更新再判斷

1. 進入首頁「智慧 5S 戰情中心」。
2. 確認頁首顯示「在線」。
3. 點「更新戰情」。
4. 等待四張統計卡、區域排名與五大分類成熟度完成更新。
5. 若剛完成的作業沒有反映，先到設定確認待同步為 0，再點「清除快取並更新」。

### 2.2 四張統計卡

| 統計卡 | 系統口徑 | 主管先問什麼 | 第一個動作 |
|---|---|---|---|
| 今日巡檢 | 今日已送出且未作廢的巡檢數 | 應巡區是否都已形成單號 | 找出未巡區與責任班別 |
| 平均得分 | 今日巡檢得分率平均 | 是否低於 85 分、是否有 0 分 | 檢查低分明細與即時控制 |
| 未結改善 | 尚未進入已結案或作廢的改善件數 | 有多少逾期、驗證中與待改善 | 先處理逾期與高嚴重度 |
| 紅牌待處置 | 尚未已完成或已結案的紅牌件數 | 哪些將到期或已逾期 | 確認暫存、責任與會辦 |

### 2.3 區域排名

首頁「區域 5S 排名」是各啟用區域最近 7 次巡檢得分率平均，最多顯示前 6 名。沒有巡檢的區域會顯示「未巡檢」。

| 正確用途 | 錯誤用途 |
|---|---|
| 找出持續進步或持續退步的區域 | 只看一次排名就評定人員績效 |
| 複製定位、目視化與防再發好做法 | 不同頻率、難度與基準未校準就直接比較 |
| 安排主管抽查與輔導資源 | 為提高排名要求現場提高分數 |
| 搭配異常項、照片與逾期一起判讀 | 只看平均分，不看重大風險 |

### 2.4 五大分類成熟度

系統依整理、整頓、清掃、清潔、素養五類的已送出巡檢明細計算成熟度，每一分類取最近最多 200 筆明細。主管應找最低分類、重複異常與跨區共通問題，再決定教育、標準、設備或資源改善。

### 2.5 戰情閱讀順序

1. 先看人身安全、重大品質、設備與生產中斷風險。
2. 再看 0 分、高嚴重度與逾期改善。
3. 再看逾期或即將到期紅牌。
4. 再看今日未巡區與低於 85 分區域。
5. 最後看排名與五大分類趨勢，安排長期改善。

## 三、每日管理節奏

### 3.1 開班

1. 核對本人角色、版本、連線與待同步。
2. 更新首頁戰情並記錄今日優先風險。
3. 到「改善」查看「逾期」與「未結案」。
4. 到「紅牌」查看「逾期」與即將到期案件。
5. 確認上一班未結案件、臨時控制與交接證據。
6. 安排今日應巡區、抽查區與驗證時段。

### 3.2 班中

- 重大異常先到現場，確認隔離、標示、停止或通報是否有效。
- 對 0 分、高嚴重度、重複異常與跨區問題進行抽查。
- 確認待改善案件已被看見，改善中案件有具體進度。
- 對驗證中案件安排現場驗證，不讓案件只停在系統裡。
- 紅牌暫存區至少抽查一次，核對實體、編號、數量與系統狀態。

### 3.3 收班

1. 確認應巡區都已形成巡檢單號。
2. 確認低於 5 分項目都有原因、現況照片與改善單。
3. 處理仍在驗證中的案件，或明確交接驗證責任與時間。
4. 確認紅牌暫存實體與系統狀態一致。
5. 確認公用裝置待同步為 0。
6. 交接所有未結案、逾期、臨時控制與下一步。

### 3.4 班別交接最低內容

| 類別 | 必交接內容 | 完成訊號 |
|---|---|---|
| 巡檢 | 未巡區、巡檢單號、0 分與重大異常 | 接班者知道需補巡或控制事項 |
| 改善 | 改善單號、狀態、責任、期限、阻礙 | 下一步與完成時間明確 |
| 紅牌 | 紅牌編號、實體位置、處置進度、到期日 | 實體可找到且狀態一致 |
| 同步 | 裝置、待同步筆數、成功與失敗結果 | 待同步 0 或已完整留證 |
| 風險 | 安全、品質、設備與生產限制 | 控制措施與解除條件明確 |

## 四、巡檢品質與主管抽查

### 4.1 主管不只看總分

主管抽查應打開來源巡檢、改善案件與現場位置，核對分數、原因、照片與實際狀況。平均分正常不代表沒有重大風險；一個 0 分或高嚴重度案件就可能需要立即處置。

### 4.2 四級分數管理意義

| 分數 | 系統嚴重度 | 主管判定 | 管理要求 |
|---|---|---|---|
| 5 分 | 不建立改善 | 完全符合且可維持 | 抽查標準是否真實一致 |
| 3 分 | 低 | 局部缺口或維持性不足 | 期限內恢復標準並防再發 |
| 1 分 | 中 | 明顯不符合、影響作業或容易再發 | 主管確認資源與短期控制 |
| 0 分 | 高 | 嚴重不符合或有立即風險 | 先停止、隔離、標示與通報，再處理案件 |

### 4.3 0 分案件立即確認

- [ ] 人員是否已離開危險區或停止不安全作業。
- [ ] 產品是否隔離，是否有混料或品質流出風險。
- [ ] 設備是否需要停機、維修或防止誤啟動。
- [ ] 現場是否已有清楚標示與責任人看守。
- [ ] 異常原因與照片是否可定位。
- [ ] 改善單是否建立，期限與責任是否可追蹤。

### 4.4 抽查照片與原因

| 抽查項目 | 合格 | 退回補正 |
|---|---|---|
| 異常原因 | 有位置、物件、數量或範圍與影響 | 只有「很亂」、「不合格」、「要改善」 |
| 現況照片 | 可辨識區域、物件、異常位置與程度 | 模糊、太近、太暗或無法定位 |
| 現場一致 | 照片與當時現況、時間及區域一致 | 舊照片、別區照片或整理後補拍 |
| 資訊安全 | 不含無關個資、密碼或機密內容 | 拍到人員名單、螢幕或受限文件 |

### 4.5 抽查不合格時

主管不得替巡檢人員編造原因或補一張無關照片。應保留原單號與原證據，要求現場補充事實，並依授權流程修正或新增說明。若資料已錯區、錯人、重複或狀態錯跳，立即停止後續寫入並回報系統管理員。

## 五、改善清單分流與責任管理

### 5.1 五種篩選

| 篩選 | 顯示內容 | 主管用途 |
|---|---|---|
| 未結案 | 尚未已結案或作廢的案件 | 每日主要工作清單 |
| 逾期 | 未結案且期限已過的案件 | 升級資源與責任 |
| 我的 | 本人工號或姓名為負責人的案件 | 個人承諾與追蹤 |
| 已結案 | 已驗證通過的案件 | 抽查維持與再發 |
| 全部 | 所有案件 | 查單號、來源與歷程 |

### 5.2 改善卡片怎麼看

| 卡片內容 | 代表意義 | 主管判斷 |
|---|---|---|
| 改善單號 | 主要追溯鍵 | 交接、回報與會議都使用此單號 |
| 區域與問題標題 | 發生位置與檢查項目 | 是否與現場及來源巡檢一致 |
| 問題說明 | 巡檢人填寫的異常事實 | 是否可定位、可驗證 |
| 嚴重度 | 0 分為高、1 分為中、3 分為低 | 資源與優先順序是否合理 |
| 負責人 | 區域主檔帶入或顯示待指派 | 是否有人承接並能完成 |
| 期限或逾期天數 | 預設建立後 7 日 | 是否需要立即升級 |

### 5.3 責任人與期限的操作邊界

目前行動端畫面沒有直接改派責任人或修改期限的按鈕。主管可以決定承接者、資源與完成承諾，但正式欄位若需變更，必須交由經授權的資料管理流程辦理並保留原值、新值、原因、執行人與時間。

> 不得直接打開中央試算表改列，也不得把期限往後改來消除逾期。若案件顯示「待指派」，先做現場控制並立刻通知區域主管與授權管理員。

### 5.4 四級分流

| 優先層級 | 條件 | 處理時限 | 主管輸出 |
|---|---|---|---|
| 立即 | 0 分、人身安全、重大品質、設備或停線風險 | 當下 | 停止、隔離、標示、通報與責任人 |
| 當班 | 1 分、高嚴重度、重複發生或跨區影響 | 本班內 | 控制措施、資源與具體下一步 |
| 三日內 | 3 分但影響維持性、目視化或交接 | 三日內 | 恢復標準與防再發 |
| 期限內 | 一般低風險改善 | 系統期限內 | 持續追蹤至送驗與結案 |

### 5.5 主管追問五句

1. 現場現在是否安全、品質是否受控？
2. 這件事由誰在什麼時間前完成？
3. 需要停機、備品、人力、工程、品保或其他資源嗎？
4. 完成時要留下哪一張照片、哪一筆紀錄或哪一個憑證？
5. 如何防止下一班或下一週再發？

## 六、改善驗證、通過與駁回

### 6.1 什麼時候會看到管理按鈕

案件必須處於「驗證中」，且本人系統角色為「主管」或「區域負責人」，畫面才會顯示「驗證通過」與「駁回改善」。按鈕不出現時，先核對案件狀態與設定頁角色，不得借用他人帳號。

### 6.2 驗證七步驟

1. 打開改善案件，記下改善單號、區域、責任與期限。
2. 讀取問題說明與改善前照片。
3. 到現場找到相同位置與物件。
4. 核對改善後照片與實際現況。
5. 檢查異常是否消除、標準是否恢復、是否引入新風險。
6. 在「處理說明／驗證意見」填寫現場事實與判定理由。
7. 合格點「驗證通過」；不合格點「駁回改善」。

### 6.3 驗證通過標準

- 原異常已消除，或已依核准方式受到持續控制。
- 定位、定量、標示、清潔與安全狀態已恢復。
- 改善前後照片角度可比對，且與現場一致。
- 處理說明寫出做法、原因、防再發與確認方式。
- 沒有只把問題移位、遮住或暫時擦掉。
- 現場已確認，責任人與接班者都知道新標準。

### 6.4 必須駁回的情況

| 駁回原因 | 現場例子 | 駁回意見必寫 |
|---|---|---|
| 問題仍存在 | 油漬清掉但接頭仍持續漏油 | 尚未排除漏油來源與再發風險 |
| 只有臨時控制 | 物品只是移到別處，沒有定位與責任 | 尚未恢復標準位置與標示 |
| 照片不足 | 改善後照片看不到原位置 | 請用相同角度補拍全景與近景 |
| 原因未處理 | 只加警示牌但未修正原因 | 請補完成因處理與確認結果 |
| 有新風險 | 改善後妨礙動線或混放物料 | 新增風險未受控，不得結案 |
| 無法現場確認 | 設備仍停機、物品去向不明 | 待可驗證後再送驗 |

### 6.5 驗證意見範例

| 判定 | 完整寫法 |
|---|---|
| 通過 | 現場確認 6 支量具均依定位歸位，名稱與上限清楚，抽查交接無缺漏，驗證通過 |
| 通過並追蹤 | 接頭與油管已更換，試運轉三十分鐘無滲漏，每班接頭目視檢查已建立，一週後複查 |
| 駁回 | 改善後照片未包含原異常位置，現場仍有 2 支量具未歸位，請完成定位並重新拍照送驗 |
| 駁回 | 地面已擦拭但油管仍滲漏，目前只有吸油棉臨時控制，請排除漏油原因後再送驗 |

## 七、逾期改善與升級處理

### 7.1 逾期代表什麼

逾期是未結案案件已超過期限，不等於只差按一次結案。主管應查明卡在哪一段：沒有人承接、資源不足、改善未完成、等待驗證、外部會辦或資料異常。

### 7.2 升級層級

| 逾期狀況 | 主管處理 | 升級對象 | 管理紀錄 |
|---|---|---|---|
| 逾期 1 至 2 日、低風險 | 當班確認原因與完成承諾 | 區域負責人 | 單號、阻礙、完成時間 |
| 逾期 3 至 7 日或中風險 | 提供人力、停機窗口或物料資源 | 單位主管、工程或品保 | 資源決議與追蹤人 |
| 超過 7 日、高風險或重複 | 專案化處理並每日追蹤 | 最高主管與相關單位 | 臨時控制、根因、里程碑 |
| 資料或權限異常 | 停止重複操作並保留證據 | 系統管理員 | 畫面、裝置、時間與單號 |

### 7.3 不得掩蓋逾期

- 不把期限改晚來消除紅色逾期標示。
- 不先點結案再補照片或憑證。
- 不把同一問題拆成多件新案來降低逾期。
- 不用另一筆假資料沖銷錯誤案件。
- 不把等待外部單位當成沒有責任人。

## 八、物品盤點與紅牌管理

### 8.1 三種必要性判定

| 判定 | 管理意義 | 主管動作 |
|---|---|---|
| 必要 | 現行工作需要，數量與位置符合基準 | 確認定位、上限與責任 |
| 待判定 | 用途、規格、責任、期限或資產屬性不明 | 指定會辦，期限內完成判定 |
| 非必要 | 長期未用、重複、過量、損壞、過期或不應在現場 | 建立紅牌、移至暫存區並追蹤處置 |

### 8.2 待判定案件怎麼處理

1. 確認物品名稱、規格、數量、原位置與照片。
2. 指定工程、品保、倉庫、環安、財務或資產管理等必要會辦。
3. 設定判定完成時間與暫時保管責任。
4. 在判定完成前不得任意丟棄、報廢或移回原位。
5. 判定完成後依授權流程更新正式結果與證據。

### 8.3 特殊物品停止點

- 化學品、油品、氣瓶與危險物需先由環安確認。
- 量具、檢具、治具與品質設備需先確認校驗、產品與品質風險。
- 固定資產、資訊設備與高價工具需完成資產或財務確認。
- 客戶財產、在製品、原料與成品不得當作一般雜物處置。
- 重物、尖銳物或需吊掛搬運的物品先完成安全評估。

### 8.4 紅牌清單篩選

| 篩選 | 顯示內容 | 主管用途 |
|---|---|---|
| 未結案 | 待處置與處理中案件 | 每日追蹤 |
| 逾期 | 已超過預定處置日且未結案 | 升級會辦與資源 |
| 已結案 | 已完成正式處置 | 抽查證據與實體一致性 |
| 全部 | 所有紅牌 | 查單號與歷程 |

### 8.5 紅牌卡片必看

紅牌卡片顯示紅牌編號、物品名稱、區域、數量、紅牌原因、案件狀態、處置建議與倒數。倒數可能顯示「剩 N 天」、「逾期 N 天」、「未設定期限」或「已結案」。主管應同步查看實體暫存區，不能只看畫面。

## 九、紅牌處置與結案

### 9.1 管理按鈕顯示條件

未結案紅牌若為「待處置」，所有使用者可看到「開始處理」；只有「主管」或「區域負責人」能看到「完成並結案」。沒有管理按鈕時，先核對本人角色與案件狀態。

### 9.2 開始處理

1. 打開紅牌詳情，核對編號、物品、數量、區域與暫存位置。
2. 確認處置建議、責任部門與預定處置日。
3. 確認實體物品與系統案件一一對應。
4. 點「開始處理」，狀態變為「處理中」。
5. 依移轉、退庫、維修、報廢、出售回收或核准保留流程執行。

### 9.3 結案證據

| 處置方式 | 必要證據 | 現場驗收 |
|---|---|---|
| 移轉 | 新位置、接收人與更新標示 | 新位置符合需求且可找到 |
| 退庫 | 退庫日期、數量、料號與接收紀錄 | 實體已離開暫存區 |
| 維修 | 故障、送修單位、預計完成日與回廠紀錄 | 未回廠前不宣稱完成 |
| 報廢 | 核准、分類、日期與實際處置證明 | 實體已依規定處置 |
| 出售或回收 | 核准、交接、數量與接收證明 | 去向與實體一致 |
| 保留 | 理由、責任人、位置、期限、核准人與複查日 | 非無限期留置 |

### 9.4 完成並結案

1. 主管或區域負責人到現場確認實體已完成核准處置。
2. 在「處置結果／說明」填寫實際日期、方式、去向與證據。
3. 點「完成並結案」。
4. 確認案件狀態變為「已結案」。
5. 確認實際處置日、處置結果證據與複查人已記錄。
6. 若紅牌有連動改善單，確認改善單也已同步進入已結案。

### 9.5 不得結案

- 實體仍在暫存區，只是口頭說已處理。
- 系統寫報廢，但實體仍在現場。
- 只有看不出物品去向的照片。
- 數量、規格或紅牌編號與實體不一致。
- 需要環安、品質、財務或資產核准但尚未完成。
- 處置後引入新的安全、品質或搬運風險。

> 紅牌結案會連動結束對應改善單。主管必須先確認兩邊代表同一件實際完成的處置，不得為了清除待辦而提前結案。

## 十、離線同步與資料一致性監督

### 10.1 主管要知道的離線邊界

畫面顯示「離線」時，部分新增資料會先排入本裝置待同步佇列。排隊只代表暫存，尚未進入中央資料庫。改善驗證、紅牌結案與權限相關管理動作，建議在「在線」且資料已更新後執行。

### 10.2 公用裝置管理

- 每位使用者作業前核對姓名與角色，換班必須登出。
- 收班前到設定確認待同步 0。
- 離線期間不得清除瀏覽器資料、移除圖示或重新安裝。
- 同一案件不得在多台裝置重複輸入或重複送出。
- 待同步未歸零時，交接裝置、本人、區域、時間、單號與筆數。

### 10.3 正確更新順序

1. 確認頁首顯示「在線」。
2. 到設定查看待同步筆數。
3. 大於 0 時點「立即同步」一次。
4. 等待成功、失敗與剩餘結果。
5. 確認待同步變為 0。
6. 點「清除快取並更新」。
7. 以單號回讀案件狀態，再回首頁點「更新戰情」。

### 10.4 必須停止操作的資料異常

| 異常 | 主管立即動作 | 必留證據 |
|---|---|---|
| 同一作業出現兩個正式單號 | 停止新增與結案 | 兩個單號、畫面、時間、裝置 |
| 補送後出現重複或錯區 | 停止後續更新 | 原單號、新單號、區域與同步結果 |
| 畫面顯示他人身分 | 登出並停止寫入 | 姓名、角色、裝置與發生時間 |
| 驗證後狀態未改 | 不重複按按鈕 | 單號、原狀態、畫面與時間 |
| 待同步不減或失敗增加 | 保留佇列、不清除資料 | 成功、失敗、剩餘與錯誤訊息 |

## 十一、LINE 通知與升級管理

### 11.1 系統建立待通知的情境

目前巡檢 0 分會建立「重大巡檢異常」待通知紀錄；新增非必要品紅牌會建立「新增紅牌」待通知紀錄。通知是否真正送達仍取決於群組識別、權杖、後端排程與發送狀態。

### 11.2 主管收到通知後

1. 先看場景、區域、問題或物品與單號。
2. 涉及立即風險時先電話、廣播或到場，不等待訊息回覆。
3. 打開智慧 5S 以單號核對正式案件。
4. 確認現場控制、責任與期限。
5. 通知內容與系統不一致時保留兩邊畫面並回報。

### 11.3 LINE 不是結案證據

群組訊息只用於提醒與升級，不能取代巡檢單、改善單、紅牌案件、照片、處置憑證與驗證結果。主管在群組回覆「收到」或「已處理」，不代表系統案件已正式結案。

### 11.4 通知異常回報

| 回報項目 | 內容 |
|---|---|
| 場景 | 重大巡檢異常或新增紅牌 |
| 來源單號 | 巡檢單號、改善單號或紅牌編號 |
| 應通知對象 | 區域群組或責任單位 |
| 實際狀況 | 未收到、重複、延遲或內容不一致 |
| 發生時間 | 系統建立時間與發現時間 |
| 畫面證據 | 系統案件、通知畫面與錯誤訊息 |

## 十三、資料、權限與資訊安全

### 13.1 資料修正原則

一般主管不直接修改中央試算表。需要修正錯人、錯區、重複、期限、責任或狀態時，交由經授權的系統管理流程保留：原值、新值、修正原因、執行人、核准人與修正時間。

### 13.2 照片安全

- 只拍案件需要的區域、物件與異常。
- 不拍無關人員名單、個人資料、密碼、客戶文件或受限圖面。
- 發現照片含敏感內容時，停止轉傳並立即回報。
- 不把系統照片下載後放到私人社群或非授權群組。

### 13.3 帳號與公用裝置

- 主管不得把管理身分借給他人執行驗證或結案。
- 公用裝置交接前完成待同步，然後登出。
- 看見他人姓名立即登出，不繼續作業。
- 離線期間仍以最後登入身分運作，更要先核對本人。

### 13.4 版本變更驗收

| 變更類型 | 必須驗收 |
|---|---|
| 角色與權限 | 主管、區域負責人與現場人員按鈕符合職責 |
| 狀態流程 | 改善與紅牌只能依核准路徑轉換 |
| 欄位與主檔 | 區域、項目、責任、期限與啟用狀態正確 |
| 離線同步 | 排隊、補送、失敗保留與回讀一致 |
| 通知 | 對象、內容、去重、時間與失敗狀態可追蹤 |
| 文件 | 管理辦法、作業程序、操作手冊與教材同步修訂 |

## 十四、主管一頁快速操作卡
