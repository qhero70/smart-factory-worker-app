## 二、系統、角色與作業邊界

### 2.1 系統組成

智慧 5S 以同一套 PWA、Google Apps Script、Google 試算表、既有 NEXUS OS LINE Bot 與 Git 版本庫運作。手機與電腦看到的畫面是操作入口，正式紀錄仍以中央資料庫與系統狀態為準。

| 組成 | 使用者看到的用途 | 正式責任 |
|---|---|---|
| PWA | 登入、巡檢、拍照、改善、紅牌、同步 | 提供一致操作與離線佇列 |
| GAS | 讀取、驗證、新增、更新、LINE 待通知處理 | 控制資料寫入與服務邏輯 |
| Google 試算表 | 人員、區域、巡檢、改善、紅牌、照片與通知紀錄 | 單一正式資料來源 |
| NEXUS OS LINE Bot | 重大異常與紅牌通知 | 沿用唯一 Bot，不另建入口 |
| GitHub | PWA、GAS、文件與版本追溯 | 每次變更都有版本紀錄 |

### 2.2 系統角色

| 系統角色 | 主要操作 | 可判定事項 | 不應執行 |
|---|---|---|---|
| 現場人員 | 登入、巡檢、拍照、改善接單、盤點、紅牌回報 | 現況評分、必要性初判、改善回報 | 驗證自己的改善、逕自結案紅牌 |
| 區域負責人 | 現場人員功能、所屬區域追蹤、改善驗證、紅牌結案 | 基準落實、驗證判定、區域處置 | 無證據結案、跨區任意改主檔 |
| 主管 | 全區追蹤、驗證、紅牌結案、KPI 複盤 | 資源與期限、驗證與處置核准 | 以分數取代現場事實判定 |
| 系統管理員 | 主檔、部署、版本、同步與異常診斷 | 技術修正與版本發布 | 代替業務主管判定改善合格 |

### 2.3 系統角色如何形成

系統會依 `01_人員主檔` 的「職稱」與「角色類型」判定角色。經理、副理、課長、主任或主管類職稱通常判定為「主管」；工程師、助理工程師、領班、組長或幹部類通常判定為「區域負責人」；其餘為「現場人員」。

> 角色不正確時，不要借用他人工號。由主檔維護者修正人員資料，使用者登出後重新登入，再核對設定頁。

### 2.4 作業邊界

- 人身安全、重大品質、設備、漏液、停線或生產中斷風險，先停止、隔離、標示與即時通報，再補系統紀錄。
- 正式作業不得使用個人副本、舊版書籤、測試入口或未核准試算表。
- 已結案紀錄不以刪除方式修正；必要時建立新案或留存修正歷程。
- 系統管理員可以修正技術問題，但不能替代現場主管完成驗證與處置判定。

## 三、裝置準備與 PWA 安裝

### 3.1 建議裝置條件

| 項目 | 建議 | 使用前檢查 |
|---|---|---|
| 手機／平板 | 近期 Android Chrome 或 iPhone Safari | 相機、儲存空間、日期時間正常 |
| 電腦 | Chrome 或 Edge | 可開啟正式入口與相機檔案選擇 |
| 網路 | 第一次登入必須連網 | 頁首狀態顯示「在線」 |
| 權限 | 允許相機、網站資料與通知所需權限 | 拍照後可看到預覽 |
| 公用裝置 | 具交接與登出規範 | 作業結束點「登出」 |

### 3.2 正式入口辨識

1. 開啟 `https://qhero70.github.io/smart-factory-worker-app/5s/?v=102`。
2. 畫面標題應為「化新精密｜智慧 5S」。
3. 登入頁下方版本應為 `1.0.2`。
4. 資料庫名稱應顯示「⭐智慧工廠主資料庫」。
5. 任一項不符時，先不要輸入或送出正式資料。

### 3.3 Android／Chrome 安裝

1. 以 Chrome 開啟正式入口。
2. 若系統提供安裝提示，可在「設定」點「安裝 PWA」。
3. 若按鈕顯示「請由瀏覽器選單安裝」，開啟 Chrome 選單後選「安裝應用程式」或「加入主畫面」。
4. 確認主畫面出現「智慧5S」圖示。
5. 從圖示開啟，確認為獨立 App 畫面且版本正確。

### 3.4 iPhone／Safari 安裝

1. 以 Safari 開啟正式入口。
2. 點選分享按鈕。
3. 選擇「加入主畫面」。
4. 名稱保留為「智慧5S」，完成新增。
5. 從主畫面圖示開啟，完成一次線上登入。

### 3.5 Windows／macOS 安裝

1. 以 Chrome 或 Edge 開啟正式入口。
2. 使用網址列安裝圖示，或從瀏覽器選單選擇安裝應用程式。
3. 完成後可建立桌面、開始功能表或 Dock 捷徑。
4. 不支援相機時，可選擇電腦中已拍攝的現況照片；仍須符合照片證據規則。

### 3.6 安裝完成驗收

- [ ] 從主畫面或桌面圖示可開啟智慧 5S。
- [ ] 登入頁版本為 1.0.2。
- [ ] 第一次登入時頁首狀態為「在線」。
- [ ] 手機相機可開啟，拍攝後可看到預覽。
- [ ] 設定頁顯示裝置識別碼與正確使用者資料。

## 四、登入、身分核對與登出

### 4.1 登入畫面地圖

| 畫面區塊 | 看到的文字 | 用途 |
|---|---|---|
| 品牌區 | 化新精密｜智慧 5S | 確認正式系統 |
| 登入欄位 | 工號或姓名 | 輸入完整工號或姓名 |
| 主要按鈕 | 登入智慧 5S | 讀取 `01_人員主檔` 並進入系統 |
| 離線提示 | 目前沒有網路 | 說明僅曾登入裝置可使用離線模式 |
| 版本資訊 | 版本 1.0.2 | 核對正式版本與主資料庫 |

### 4.2 第一次登入

1. 確認頁首或裝置網路為在線。
2. 在「工號或姓名」輸入完整工號；必要時可輸入完整姓名。
3. 點「登入智慧 5S」。
4. 等待「核對人員資料」與核心資料載入完成。
5. 首頁出現後，點右上角頭像或底部「設定」。
6. 核對姓名、工號、部門、組別、職稱與系統角色。

### 4.3 登入完成訊號

| 檢查點 | 正確結果 | 不正確時 |
|---|---|---|
| 首頁稱呼 | 顯示本人姓名 | 立即登出，禁止繼續作業 |
| 系統角色 | 與實際權限相符 | 請主檔維護者修正角色來源 |
| 部門／組別 | 與現場責任一致 | 修正 `01_人員主檔` 後重登 |
| 核心資料 | 可看到啟用巡檢區域 | 通知管理員檢查區域與清單主檔 |
| 連線狀態 | 在線或已知的離線狀態 | 離線時只執行允許作業 |

### 4.4 常見登入訊息

| 畫面訊息 | 代表原因 | 使用者處理 |
|---|---|---|
| 請輸入工號或姓名 | 欄位為空白 | 輸入後再登入 |
| 人員主檔找不到此工號或姓名 | 未查到啟用對應資料或回傳解析異常 | 保留輸入值與畫面，請管理員查核主檔 |
| 此人員目前已停用 | `啟用` 欄為「否」 | 請主管確認任職與權限狀態 |
| 核心資料載入失敗 | 區域或檢查項目讀取失敗 | 轉到設定頁，確認網路後更新 |
| 目前沒有網路 | 裝置離線 | 首次登入改為連網；曾登入者只做允許離線作業 |

### 4.5 公用裝置登出

1. 完成當班操作並先確認「待同步 0」。
2. 進入底部「設定」。
3. 點「登出」。
4. 在確認視窗選擇確定。
5. 畫面回到工號登入頁，再交給下一位使用者。

> 登出前若仍有待同步資料，應先完成補送或以單號、裝置、筆數完成交接。不得以清除瀏覽器資料或移除 PWA 代替正常同步。

## 六、首頁戰情中心

### 6.1 首頁資訊

首頁會讀取巡檢主檔、巡檢明細、改善單與紅牌追蹤，顯示今日作業及近期趨勢。

| 卡片 | 計算內容 | 判讀方式 |
|---|---|---|
| 今日巡檢 | 今日非作廢巡檢單數 | 0 代表尚未有正式送出紀錄 |
| 平均得分 | 今日巡檢得分率平均 | 低於 85 分需檢視異常與改善 |
| 未結改善 | 尚未結案的改善案件 | 同時顯示逾期件數 |
| 紅牌待處置 | 未完成或未結案紅牌 | 依 30 天期限追蹤 |
| 區域 5S 排名 | 各區近 7 次巡檢平均 | 用於找趨勢，不直接作個人績效 |
| 五大分類成熟度 | 近期巡檢明細的加權得分 | 比較整理、整頓、清掃、清潔、素養 |

### 6.2 快速作業入口

| 快速卡 | 進入頁面 | 使用情境 |
|---|---|---|
| 開始巡檢 | 巡檢 | 班前、定期或主管抽查 |
| 改善追蹤 | 改善 | 接單、回報、送驗或驗證 |
| 物品盤點 | 直接開啟新增盤點 | 發現待判定或非必要品 |
| 紅牌處置 | 紅牌 | 追蹤暫存天數與處置結果 |

### 6.3 更新戰情

1. 點「更新戰情」。
2. 等待巡檢、改善與紅牌資料讀取完成。
3. 比對今日巡檢數、未結改善與紅牌件數是否變動。
4. 若剛完成作業但數字未更新，先到設定確認待同步，再重新更新戰情。

### 6.4 主管閱讀順序

1. 先看逾期改善與紅牌待處置，確認有無立即風險。
2. 再看今日巡檢與平均得分，找出未巡區或低分區。
3. 用五大分類成熟度定位長期薄弱類別。
4. 用區域近 7 次排名找趨勢、交流好做法與安排資源。
5. 不以單一分數直接獎懲；先確認基準、巡檢次數、難度與資料完整性。

## 七、開始一張巡檢單

### 7.1 進入巡檢

1. 從首頁點「立即開始巡檢」，或底部點「巡檢」。
2. 在「巡檢區域」找到實際所在區域。
3. 核對區域代碼、區域名稱、巡檢頻率與檢查清單代碼。
4. 點選區域卡片，系統依清單順序載入檢查項目。

### 7.2 選區前確認

| 確認項目 | 正確做法 | 錯誤風險 |
|---|---|---|
| 實際位置 | 人員站在被巡區域或能明確辨識現況 | 選錯區造成責任與照片錯置 |
| 區域代碼 | 與現場標示一致 | 同名區域無法正確追溯 |
| 清單代碼 | 與該區核准清單一致 | 使用錯誤判定基準 |
| 巡檢頻率 | 符合當日／當班要求 | 重複巡檢或漏巡 |

### 7.3 巡檢表單構成

| 畫面區塊 | 內容 | 使用方式 |
|---|---|---|
| 巡檢頁頭 | 區域名稱、清單代碼、完成項數 | 隨評分更新進度 |
| 項目序號 | 項目順序與 5S 分類色 | 依序檢查，不跳項 |
| 檢查內容 | 要檢查的對象 | 以現場實物確認 |
| 判定基準 | 核准的合格條件 | 不用個人印象取代基準 |
| 權重標示 | 重大權重 ×N | 重大項影響總分，仍依事實評分 |
| 5／3／1／0 | 四級評分 | 低於 5 分自動展開異常區 |
| 整體備註 | 本張巡檢單補充說明 | 選填，不取代逐項異常原因 |

### 7.4 取消巡檢

點「取消」時，系統會詢問是否放棄尚未送出的巡檢。確認後，本次未送出內容不形成正式紀錄。已有必要證據但尚未送出時，先評估是否應保留照片或重新建案，不要誤按取消。

## 八、評分、異常原因與照片

### 8.1 四級評分

| 評分 | 畫面文字 | 判定原則 | 系統結果 |
|---|---|---|---|
| 5 | 符合 | 完全符合核准基準 | 建立巡檢明細，不建立改善單 |
| 3 | 輕微 | 有輕微偏差或可快速復原 | 原因與照片必填，建立低嚴重度改善 |
| 1 | 異常 | 明顯不符，需要責任與期限追蹤 | 原因與照片必填，建立中嚴重度改善 |
| 0 | 重大 | 涉及安全、品質、設備或重大現場風險 | 先即時控制，建立高嚴重度改善與待通知 |

### 8.2 評分操作

1. 閱讀「檢查內容」與「判定基準」。
2. 觀察實物、數量、位置、標示、期限與清潔狀態。
3. 點選 5、3、1 或 0；選中的分數會呈現作用狀態。
4. 若點錯，可直接改點另一個分數。
5. 改回 5 分時，系統會清除該項異常原因與照片，請確認確實完全符合。

### 8.3 異常原因寫法

原因至少包含「位置、現況、程度或數量、需要的結果」。

| 不完整寫法 | 建議寫法 |
|---|---|
| 很亂 | A9 1069 檢驗桌左側有 6 支未定位量具，應依治具板標示歸位 |
| 不乾淨 | 1070 檢驗桌下方發現約 20 公分油污，已隔離並需查明來源 |
| 東西太多 | 簡單專線周轉區超出標示上限 3 箱，需移轉並恢復通道寬度 |
| 標籤錯 | A9 紅牌暫存區第 2 格物品與標籤名稱不符，需重新核對與標示 |

### 8.4 拍攝異常照片

1. 點「📷 拍攝異常現況」。
2. 相機開啟後，先拍到區域或定位標示，再拍清楚異常本體。
3. 等待按鈕顯示「照片壓縮中」完成。
4. 確認出現照片預覽與「已拍攝，可重新選擇」。
5. 照片不清楚時重新拍攝；不要使用舊照或他區照片。

### 8.5 照片合格檢查

- [ ] 能辨識區域與異常位置。
- [ ] 異常本體、數量或程度清楚。
- [ ] 沒有證件、薪資、醫療、密碼或私人通訊內容。
- [ ] 改善前照片能與後續改善後照片比較。
- [ ] 預覽已完成，沒有仍停在壓縮中。

### 8.6 照片過大或格式失敗

若顯示照片仍過大、無法讀取或格式無法處理：

1. 靠近拍攝主體，減少無關背景。
2. 改用手機相機直接拍攝，不選用特殊格式或編輯檔。
3. 檢查相機權限與裝置儲存空間。
4. 重新開啟該項照片按鈕拍攝。
5. 仍失敗時保留畫面與項目位置，依第十九章通報。

## 九、送出巡檢與讀懂結果

### 9.1 送出前自我檢查

- [ ] 所有低於 5 分的項目都有清楚現況照片。
- [ ] 0 分重大異常已先控制並即時通報。

## 十一、開始改善、回報與送驗

### 11.1 改善狀態路徑

| 原狀態 | 畫面按鈕 | 新狀態 | 必要資料 |
|---|---|---|---|
| 待改善 | 開始改善 | 改善中 | 案件與責任確認 |
| 已駁回 | 開始改善 | 改善中 | 讀取駁回原因並重新處理 |
| 改善中 | 完成並送驗 | 驗證中 | 處理說明、改善後照片 |
| 驗證中 | 驗證通過 | 已結案 | 管理角色、驗證意見 |
| 驗證中 | 駁回改善 | 改善中 | 管理角色、具體駁回原因 |

### 11.2 接單並開始改善

1. 在「改善」頁選「我的」或「未結案」。
2. 點開案件，核對單號、區域、分類、問題、負責人與期限。
3. 對照「改善前」照片到現場確認。
4. 點「開始改善」，狀態變為「改善中」。
5. 執行原因排除、復原、標準化、教育或工程改善。

### 11.3 撰寫處理說明

處理說明應回答「做了什麼、改善到哪裡、如何防止再發」。

| 不完整寫法 | 建議寫法 |
|---|---|
| 已處理 | 已將 6 支量具依治具板定位歸位，補上名稱與數量上限，並由當班人員交接確認 |
| 清好了 | 已清除檢驗桌下方油污，鎖緊接頭並放置吸油棉，安排次班確認是否再漏 |
| 移走了 | 已將超量 3 箱移轉至核准周轉區，恢復通道寬度並更新定位上限 |

### 11.4 拍攝改善後照片

1. 在「改善中」案件點「📷 拍攝改善後照片」。
2. 使用與改善前相近的角度、距離與範圍。
3. 同時拍到新定位、標示、數量、清潔或防錯措施。
4. 等待預覽完成，確認照片清楚。
5. 填寫處理說明後點「完成並送驗」。

### 11.5 送驗完成訊號

- 狀態顯示「驗證中」。
- 改善後照片出現在案件照片對比區。
- 改善歷程保留「完成並送驗」、執行人、時間與說明。
- 驗證人可以在管理角色下看到「驗證通過」與「駁回改善」。

> 完成並送驗不是結案。改善負責人仍應追蹤驗證結果；案件只有在合格驗證後才進入已結案。

## 十二、改善驗證、駁回與結案

### 12.1 驗證前提

驗證由主管或區域負責人執行，原則上不得由改善執行人驗證自己的案件。驗證前應到現場確認，不能只看文字與照片。

### 12.2 驗證步驟

1. 進入「改善」，篩選「未結案」或「全部」。
2. 點開狀態為「驗證中」的案件。
3. 核對來源問題、改善前後照片、責任、期限與處理說明。
4. 到現場確認異常已消除、基準已恢復且沒有轉移風險。
5. 確認必要的定位、標準、教育或防錯已存在。
6. 在「處理說明／驗證意見」寫下具體判定。
7. 合格點「驗證通過」；不合格點「駁回改善」。

### 12.3 合格與駁回判定

| 判定 | 最低條件 | 畫面結果 |
|---|---|---|
| 驗證通過 | 異常消除、基準恢復、照片可比對、現場確認、無新增風險 | 已結案，寫入驗證人、時間、結果與結案時間 |
| 駁回改善 | 問題仍在、照片不足、只有移位、原因未排除、標準未更新 | 回到改善中，記錄駁回原因 |

### 12.4 驗證意見範例

| 情境 | 建議文字 |
|---|---|
| 通過 | 現場確認 6 支量具均依定位歸位，名稱與上限清楚，抽查交接無缺漏，驗證通過 |
| 駁回 | 量具已移位但治具板名稱與數量上限仍缺，無法維持；請補標準化後重新送驗 |
| 通過附追蹤 | 漏油已排除且 24 小時未再發，吸油棉與日點檢已建立，驗證通過並於一週後複查 |

### 12.5 驗證後檢查

- [ ] 畫面新狀態正確。
- [ ] 驗證意見可說明為何通過或駁回。
- [ ] 驗證人、驗證時間與改善歷程已留存。
- [ ] 已結案案件可用「已結案」篩選回查。
- [ ] 駁回案件已通知改善負責人並確認新行動。

## 十三、物品盤點與紅牌建立

### 13.1 進入新增盤點

1. 從首頁點「物品盤點」，或底部「紅牌」。
2. 點主視覺中的「＋ 新增物品盤點」，也可使用右下角浮動「＋」。
3. 系統開啟「新增物品盤點」表單。

### 13.2 盤點欄位說明

| 欄位 | 是否必填 | 填寫方式 |
|---|---|---|
| 區域 | 是 | 選擇物品實際所在的啟用區域 |
| 位置 | 是 | 寫明桌、架、格、線旁或暫存位置 |
| 物品名稱 | 是 | 使用現場共同名稱，不寫「雜物」 |
| 規格型號 | 選填 | 有型號、料號、尺寸時填寫 |
| 數量／單位 | 是 | 輸入實際數量與單位 |
| 使用頻率 | 是 | 每日、每週、每月、很少使用、用不到 |
| 必要性判定 | 是 | 必要、待判定、非必要 |
| 判定理由 | 非必要時必填 | 說明未使用、重複、過量、過期或損壞等事實 |
| 建議處置 | 建議填寫 | 保留原位、移轉、退庫、報廢評估、出售或回收、待會審 |
| 物品現況照片 | 非必要時必填 | 清楚拍到物品、位置與標示 |
| 備註 | 選填 | 補充資產、客戶財產、待會辦等限制 |

### 13.3 必要性判定

| 判定 | 適用條件 | 系統行為 |
|---|---|---|
| 必要 | 當期作業需要且符合位置、數量與期限 | 建立物品盤點紀錄 |
| 待判定 | 需要主管、工程、品保、環安或財務會辦 | 建立盤點，紅牌需求為待確認 |
| 非必要 | 用不到、很少使用、重複、過量、過期、損壞或不應留在現場 | 建立盤點、紅牌、改善、歷程、照片與待通知紀錄 |

### 13.4 建立非必要品紅牌

1. 選擇「非必要」。
2. 填寫具體判定理由。
3. 選擇建議處置。
4. 點「📷 拍攝物品現況」，等待照片預覽。
5. 點「儲存盤點」。
6. 記錄建立的盤點編號與紅牌編號。
7. 依現場規範將實物移到 A9 紅牌暫存區並完成實體標示。

### 13.5 系統自動建立內容

| 正式紀錄 | 主要內容 |
|---|---|
| 物品盤點 | 位置、物品、數量、頻率、必要性、理由、照片 |
| 紅牌追蹤 | 紅牌編號、掛牌日、暫存位置、建議處置、30 天期限、待處置 |
| 改善單 | 來源紅牌、整理分類、問題與期限 |
| 改善歷程 | 紅牌建立改善單的動作軌跡 |
| 照片 | 盤點照片與參照單號 |
| 通知紀錄 | 新增紅牌的 LINE 待通知資料 |

### 13.6 特殊物品停止點

涉及固定資產、客戶財產、檢量具、化學品、環安、個資、財務帳務或法定保存文件時，只能先建立紀錄與隔離，不得直接報廢或移轉。依原管制程序完成會辦與核准後，再進行紅牌結案。

## 十四、紅牌追蹤、處置與結案

### 14.1 紅牌清單與篩選

| 篩選 | 內容 | 管理用途 |
|---|---|---|
| 未結案 | 待處置或處理中的紅牌 | 每日追蹤主清單 |
| 逾期 | 已超過預定處置日且未結案 | 主管升級處理 |
| 已結案 | 已完成或已結案 | 稽核與成果追溯 |
| 全部 | 所有紅牌 | 盤點、比較與查核 |

### 14.2 紅牌卡片判讀

紅牌卡片顯示紅牌編號、物品名稱、區域、數量、原因、案件狀態、處置建議與倒數。倒數可能顯示「剩 N 天」、「逾期 N 天」、「未設定期限」或「已結案」。

### 14.3 開始處理

1. 點開狀態為「待處置」的紅牌。
2. 核對實物、紅牌編號、數量、暫存位置與原因。
3. 確認責任部門與處置方式。
4. 點「開始處理」，狀態變為「處理中」。
5. 完成移轉、退庫、核准報廢、出售回收或核准保留程序。

### 14.4 可接受的處置證據

| 處置方式 | 至少保留的證據 | 不可結案情況 |
|---|---|---|
| 移轉 | 新位置、接收單位或負責人、現況說明 | 只移到另一個未管制角落 |
| 退庫／返還 | 收受單位、日期、數量與收受人 | 實物仍留在紅牌區 |
| 報廢／回收 | 核准、會辦、處置日與實際結果 | 只有建議報廢、尚未核准 |
| 核准保留 | 理由、數量上限、新定位、責任人與核准人 | 保留後仍無定位或上限 |

### 14.5 完成並結案

1. 主管或區域負責人到現場確認處置完成。
2. 在「處置結果／說明」填寫實際結果。
3. 點「完成並結案」。
4. 系統寫入實際處置日、處置結果證據、複查人與已結案狀態。
5. 若紅牌連動改善單，系統同步將改善單結案並寫入驗證資訊。
6. 以「已結案」篩選回查，確認單號與說明可讀。

> 「完成並結案」只對主管或區域負責人顯示。沒有按鈕時先核對角色，不要改用他人帳號。

## 十五、離線作業與恢復補送

### 15.1 什麼是待同步佇列

當裝置離線或網路錯誤時，系統可把允許的新增、更新工作先存入此裝置的 IndexedDB 待同步佇列。這代表資料尚未全部進入中央資料庫，不能只看到「已排隊」就當作正式完成。

### 15.2 離線時建議作業

| 作業 | 離線建議 | 原因 |
|---|---|---|
| 新巡檢 | 可依畫面執行並保留單號與排隊筆數 | 新增資料可排隊補送 |
| 新物品盤點 | 可依畫面執行並保留編號 | 可能同時建立多筆連動資料 |
| 改善送驗 | 能連網時再執行 | 避免多人同時更新舊列號 |
| 改善驗證／駁回 | 優先在線執行 | 屬關鍵狀態判定 |
| 紅牌結案 | 優先在線執行 | 需回讀連動改善單與最新狀態 |
| 主檔、版本、通知變更 | 不允許離線處理 | 需中央一致性與核准 |

### 15.3 離線送出後

1. 記錄巡檢單號、盤點編號或紅牌編號。
2. 記錄「離線排隊 N 筆」。
3. 不重做同一張巡檢或重複儲存同一物品。
4. 不清除瀏覽器資料、不移除 PWA、不還原手機。
5. 在班別交接時告知裝置與待同步筆數。

### 15.4 恢復網路後補送

1. 確認頁首狀態為「在線」。
2. 進入底部「設定」。
3. 查看「離線同步」的待同步筆數。
4. 待同步大於 0 時點「立即同步」。
5. 等待顯示成功、失敗與剩餘筆數。
6. 目標為失敗 0、剩餘 0。
7. 點「清除快取並更新」，回到首頁或相關頁面以單號回讀。

### 15.5 補送失敗時

| 現象 | 先做什麼 | 不要做什麼 |
|---|---|---|
| 待同步不減 | 截圖筆數、時間與網路狀態 | 不連續重按同步 |
| 失敗增加 | 記錄最後錯誤與工作類型 | 不刪除佇列 |
| 部分成功 | 保留成功、失敗、剩餘數字 | 不重建全部業務資料 |
| 回讀缺列／錯列 | 以單號查正式資料並通報 | 不人工搬移試算表欄位 |
| 疑似重複 | 暫停補送，提供裝置與單號 | 不自行刪除正式紀錄 |

## 十七、LINE 通知與使用者責任

### 17.1 會建立待通知的情境

| 情境 | 建立條件 | 去重依據 |
|---|---|---|
| 重大巡檢異常 | 巡檢項目評為 0 分 | 巡檢單號＋項目代碼 |
| 新增非必要品紅牌 | 盤點判定為非必要 | 紅牌編號 |

### 17.2 使用者看到什麼

PWA 完成業務資料後建立待通知紀錄；既有 NEXUS OS 唯一 LINE Bot 由正式觸發器處理。使用者不需要也不得另建 Bot、Token、群組入口或私自轉接通知。

### 17.3 LINE 不是唯一通報

人身安全、重大品質、停線、漏液、設備破損或生產中斷風險，必須先用現場警示、口頭、電話或既有緊急程序通報。LINE 是可追溯通知通道，不可取代即時控制。

### 17.4 通知異常回報資料

- 通知場景與業務單號。
- 去重鍵或紅牌編號。
- 預期收件區域／群組。
- 發生日期時間。
- 畫面或通知紀錄顯示的狀態與錯誤。
- 是否已完成現場即時通報。

## 十九、故障排除與回報

### 19.1 標準排查順序

1. 確認正式入口、PWA 版本與頁首連線狀態。
2. 核對設定頁姓名、工號、角色與裝置識別碼。

6. 仍異常則停止重複操作，提供證據給系統管理員。

### 19.2 常見問題處理表

|---|---|---|---|

## 二十二、常見問答

### 22.1 為什麼低於 5 分一定要原因和照片？

因為 3、1、0 分都會形成改善責任。沒有原因與照片，無法判斷問題、安排改善或比較前後，也無法完成公正驗證。

### 22.2 拍照後可以立刻離開頁面嗎？

不可以。先等照片預覽出現、壓縮完成，再繼續評分或送出。

### 22.3 離線排隊代表已經進入中央資料庫嗎？

不是。代表工作保存在本裝置，仍須恢復網路後「立即同步」，直到剩餘 0 並回讀確認。

### 22.4 為什麼我看不到「驗證通過」？

只有案件為「驗證中」且目前角色為主管或區域負責人時才顯示。先核對案件狀態與設定頁角色。

### 22.5 為什麼我看不到「完成並結案」紅牌按鈕？

紅牌未結案且目前角色為主管或區域負責人時才可結案；現場人員可回報，但不能代替管理者完成處置判定。

### 22.6 可以把非必要品先移到別的角落再結案嗎？

不可以。移轉必須有核准的新位置、接收責任與現場證據；只換一個未管制位置仍屬未完成。

### 22.7 可以用名字登入嗎？

可以輸入完整姓名，但同名或部分姓名可能造成辨識困難。正式作業優先使用完整工號。

### 22.8 公用手機換人使用要怎麼做？

先確認待同步 0，再到設定點「登出」，回到登入頁後由下一位以自己的工號登入。

### 22.9 首頁數字沒有變怎麼辦？

先確認待同步為 0，再點首頁「更新戰情」；仍未更新時，到設定點「清除快取並更新」並以單號回讀。

### 22.10 可以直接修改試算表修正錯誤嗎？

一般使用者不可以。由系統管理員依核准流程保留原值、新值、原因、執行人與時間後修正，避免列號與欄位錯位。
