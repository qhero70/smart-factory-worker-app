## 二、目的、範圍與程序總覽

### 2.1 目的

本 SOP 將智慧 5S 管理辦法轉為可直接執行的步驟，確保不同人員在手機、平板或電腦上，使用同一份正式資料、相同判定與一致狀態流程，完成復原、巡檢、改善、驗證、紅牌處置、通知與複盤。

### 2.2 適用範圍

適用於已在 `5S_區域主檔` 啟用並完成基準核准的區域。第一階段為 A9 簡單專線示範區、A9 1069 檢驗桌、A9 1070 檢驗桌與 A9 紅牌暫存區。

## 三、共通作業規則

### 3.1 作業前檢查

1. 網址為已公告的正式 PWA 入口，版本顯示 1.0.2。
2. 登入人員、部門、組別、職稱與系統角色正確。
3. 區域名稱、區域代碼與檢查清單代碼符合現場。
4. 手機相機、儲存空間、日期時間與網路狀態無異常。
5. 不借用他人工號，不用舊版書籤、個人副本或測試資料執行正式作業。

### 3.2 照片證據規則

| 要求 | 合格做法 | 不合格範例 |
|---|---|---|
| 可識別 | 同時拍到區域、物品與異常位置 | 只有局部特寫，無法判斷位置 |
| 可比對 | 改善前後使用相近方向與距離 | 前後角度完全不同 |
| 可追溯 | 照片與當次單號、時間及區域相符 | 使用舊照片、他區照片或網路圖片 |
| 無敏感資料 | 避開證件、薪資、醫療與私人通訊 | 異常旁顯示個資或內部密碼 |
| 檔案可處理 | 等待預覽與壓縮完成再繼續 | 顯示照片壓縮中時立即離開頁面 |

### 3.3 即時控制優先

發現人身安全、重大品質、漏液、停線、設備破損或生產中斷風險時，先停止作業、隔離、標示與口頭或電話通報，再建立系統紀錄。不得因正在拍照、填寫或等待 LINE 而延誤控制。

### 3.4 完成與停止訊號

| 作業 | 完成訊號 | 必須停止並通報的情況 |
|---|---|---|
| 登入 | 首頁顯示本人姓名與正確角色 | 人員主檔無此人、已停用或身分錯誤 |
| 巡檢 | 顯示巡檢已完成、單號與同步結果 | 處理中斷、單號未顯示或疑似重複送出 |
| 改善 | 狀態為驗證中且有改善後照片 | 案件列號缺失、照片無法讀取或負責人錯誤 |
| 驗證 | 顯示已結案或駁回後改善中 | 驗證人與執行人相同或權限不符 |
| 紅牌 | 有紅牌編號、暫存位置與預定處置日 | 資產、客戶財產或化學品未完成會辦 |
| 離線補送 | 待同步 0 並回讀到正式資料 | 待同步不減、失敗增加或出現重複單號 |

## 四、SOP-01｜PWA 安裝、入口與登入

### 4.1 作業步驟

1. 以公司公告連結開啟 `https://qhero70.github.io/smart-factory-worker-app/5s/?v=102`。
2. 確認登入畫面版本為 1.0.2，資料庫顯示「⭐智慧工廠主資料庫」。
3. Android／Chrome 使用「安裝 PWA」；iPhone／Safari 使用分享按鈕後選「加入主畫面」。
4. 在「工號或姓名」輸入完整工號或姓名，點選「登入智慧 5S」。
5. 系統讀取 `01_人員主檔`。進入首頁後，點選右上角頭像或底部「設定」。
6. 核對姓名、工號、部門、組別、職稱與「系統角色」。
7. 使用公用裝置作業完畢時，於「設定」點選「登出」。

### 4.2 驗收與異常處理

| 檢查點 | 通過標準 | 異常處理 |
|---|---|---|
| 入口 | 網址、版本與資料庫名稱正確 | 刪除舊書籤，重新以正式入口安裝 |
| 人員 | 工號或姓名對應唯一啟用人員 | 出現「人員主檔找不到」時，記錄輸入值並查核 `01_人員主檔` |
| 角色 | 顯示主管、區域負責人或現場人員 | 修正職稱或角色類型，登出後重新登入 |
| 離線登入 | 本裝置曾成功登入者可讀取快取人員 | 首次登入必須聯網；無快取時不得借用他人帳號 |

## 五、SOP-02｜區域、清單與基準啟用

### 5.1 啟用前必備資料

| 對象 | 必備內容 | 負責人 | 核准人 |
|---|---|---|---|
| 區域 | 代碼、名稱、部門、負責人工號、清單代碼 | 區域負責人 | 區域主管 |
| 現場基準 | 邊界、定位線、名稱、數量上限、有效期、責任標示 | 區域負責人、種子教官 | 區域主管 |
| 基準照片 | 合格狀態、必要視角、拍攝日期與區域 | 區域負責人 | 區域主管 |
| 檢查清單 | 項目代碼、5S 分類、內容、判定基準、權重、順序、啟用 | 種子教官、管理員 | 區域主管 |
| LINE 收件 | 群組識別碼、雙人確認與單筆測試 | LINE 群組管理者 | 區域主管 |

### 5.2 啟用步驟

1. 區域負責人與種子教官在現場完成必要性判定、定位與基準照片。
2. 將區域代碼、負責人工號與檢查清單代碼寫入 `5S_區域主檔`。
3. 將項目代碼、判定基準、權重、順序與啟用狀態寫入 `5S_檢查項目`。
4. 區域主管以實物、照片與清單逐項核對；不合格項先修正。
5. 使用測試標記完成一次完整巡檢、一次低於 5 分改善與一次離線補送。
6. 確認回寫、照片、狀態流轉都正確後，再將區域設為啟用。

> 未建立責任人、檢查清單或基準照片的區域，不得以空白標準先上線再補資料。

## 六、SOP-03｜班前、交接與收班復原

### 6.1 作業順序

1. 以區域基準照片對照通道、桌面、工具、文件、清潔用品、樣品與待處理物品。
2. 將可當班排除的移位、數量超限、標籤歪斜、工具未歸位或少量污染先復原。
3. 無法當班排除、需跨部門、涉及安全品質或重複發生者，進入 SOP-04 建立改善單。
4. 不需要或待判定物品，進入 SOP-07 物品盤點與紅牌程序。
5. 交接時主動告知未結改善單、紅牌暫存品、臨時對策與待同步筆數。

### 6.2 完成標準

- 通道、逃生與消防區無阻擋。
- 必要物品符合一物一位、名稱、數量上限與有效期。
- 清掃中發現的漏液、破損、切屑、粉塵或工具異常已排除或建案。
- 交接資訊能以改善單號、紅牌編號或巡檢單號追溯。

## 七、SOP-04｜5S 行動巡檢

### 7.1 進入巡檢

1. 從首頁點選「立即開始巡檢」，或底部導覽「巡檢」。
2. 在「巡檢區域」點選實際所在區域，核對區域名稱與檢查清單代碼。
3. 系統依 `5S_檢查項目` 顯示順序、判定基準、5S 分類與重大權重。

### 7.2 逐項評分

| 畫面按鈕 | 判定 | 必做動作 | 送出後結果 |
|---|---|---|---|
| 5／符合 | 完全符合已核准基準 | 確認現況與基準一致 | 保留巡檢明細 |
| 3／輕微 | 有輕微偏差或需復原 | 填異常原因並拍現況 | 建立低嚴重度改善單 |
| 1／異常 | 明顯不符且需責任追蹤 | 填原因、拍照並確認控制 | 建立中嚴重度改善單 |
| 0／重大 | 安全、品質、設備或現場重大異常 | 先立即控制與通報，再填原因、拍照 | 建立高嚴重度改善單與待通知 |

### 7.3 異常原因寫法

異常原因至少包含「位置、現況、數量或程度、需要的結果」。

| 不完整 | 可執行的寫法 |
|---|---|
| 很亂 | 1069 檢驗桌右側放置 6 支無定位筆具，超過基準上限 2 支，需移除多餘並恢復定位。 |
| 漏油 | A9 專線 2 號機後方地面約 20 公分油漬，已警示與放置吸油材，需查明漏點並清理。 |
| 標示不清 | 1070 檢驗桌量具區兩枚標籤磨損，無法辨識名稱與數量上限，需重製並核對定位。 |

### 7.4 送出與確認

1. 確認頁首進度為「已完成項目數／全部項目數」。
2. 低於 5 分者必須有異常原因與現況照片，否則系統不允許送出。
3. 必要時填「整體備註（選填）」，點選「送出巡檢」。
4. 等待處理完成，不在「送出巡檢資料」畫面重複點擊、返回或關閉 PWA。
5. 記錄巡檢單號 `5S-INS-...`、得分率、異常項數、已同步與離線排隊筆數。
6. 離線排隊大於 0 時，班別結束前執行 SOP-09。

### 7.5 系統自動建立紀錄

| 條件 | 自動建立 | 預設狀態／期限 |
|---|---|---|
| 每次送出 | `5S_巡檢主檔`、`5S_巡檢明細` | 巡檢狀態「已送出」 |
| 有拍照 | `5S_照片` | 參照類型「巡檢異常」 |
| 單項低於 5 分 | `5S_改善單`、`5S_改善歷程` | 待改善／建立日起 7 日 |
| 單項等於 0 分 | `5S_通知紀錄` | 重大巡檢異常／待發送 |

## 八、SOP-05｜改善接單、處理與送驗

### 8.1 查找與接單

1. 點選底部「改善」，以「我的」查看本人案件，或以「未結案」「逾期」查看優先案件。
2. 點開改善卡片，核對改善單號、區域、5S 分類、問題、嚴重度、負責人、期限與改善前照片。
3. 確認可開始後，點選「開始改善」，狀態由「待改善」轉為「改善中」。
4. 負責人或期限明顯錯誤時，不以他人帳號替代執行；先請區域主管處理指派或例外。

### 8.2 改善執行

1. 確認異常是否仍存在，並比對基準照片、標籤、數量上限與判定基準。
2. 採取可移除原因的對策，不只為拍照短暫整理。
3. 如需跨部門、採購、工程、設備、資產或環安衛處理，於期限前回報主管，記錄臨時對策與新期限。
4. 完成後以與改善前相近視角拍攝「改善後照片」。
5. 在「處理說明／驗證意見」寫明做了什麼、結果如何、如何防止再發。
6. 點選「完成並送驗」，狀態轉為「驗證中」。

### 8.3 送驗前檢查

- 問題已實際排除，不只改變拍攝角度。
- 改善後照片可辨識區域、定位、標籤與結果。
- 說明可讓未參與的驗證人理解對策與成效。
- 涉及跨部門或資產處置者，已保留必要會辦證據。
- 未完成的臨時控制不得操作為「完成並送驗」。

## 九、SOP-06｜改善驗證、駁回與結案

### 9.1 驗證資格與步驟

僅系統角色為「主管」或「區域負責人」者可驗證。改善執行人不得驗證本人案件；重大異常優先由區域主管驗證。

1. 在「改善」選「未結案」，點開狀態為「驗證中」的案件。
2. 先查改善前照片、問題說明與原判定基準，再查改善後照片與處理說明。
3. 到現場確認實際狀態，檢查定位、標籤、數量上限、責任或防再發是否完整。
4. 確認有效時填寫驗證意見，點選「驗證通過」。
5. 尚未排除、證據不足、只有臨時整理或容易再發時，填寫具體原因，點選「駁回改善」。

### 9.2 驗證結果

| 判定 | 畫面動作 | 新狀態 | 必留資料 |
|---|---|---|---|
| 通過 | 驗證通過 | 已結案 | 驗證人工號、時間、結果、結案時間 |
| 駁回 | 駁回改善 | 改善中 | 驗證人工號、時間、「駁回：」原因、改善歷程 |

### 9.3 不得通過的情況

- 改善後照片無法對應原異常或使用舊照片。
- 現場與照片不一致，或只為拍照短暫移開物品。
- 數量上限、定位、標籤、責任或清掃週期仍未建立。
- 需要跨部門會辦但尚未完成，或只有臨時控制。
- 改善執行人與驗證人為同一人。

## 十、SOP-07｜全物品盤點與紅牌建立

### 10.1 新增物品盤點

1. 點選底部「紅牌」，再點「＋ 新增物品盤點」或右下角「＋」。
2. 選擇區域，填位置、物品名稱、規格型號、數量與單位。
3. 選擇使用頻率：每日、每週、每月、很少使用或用不到。
4. 選擇必要性判定：必要、待判定或非必要。
5. 填判定理由、建議處置，必要時拍攝物品現況，點選「儲存盤點」。

### 10.2 必要性判定

| 判定 | 適用情況 | 必填／必做 | 系統結果 |
|---|---|---|---|
| 必要 | 現行作業所需，有明確頻率與保留上限 | 定位、標示、數量與責任 | 建立盤點紀錄 |
| 待判定 | 權屬、用途、資產或需求尚需確認 | 理由、確認人與確認日期 | 紅牌需求「待確認」 |
| 非必要 | 長期未用、重複、過量、過期、損壞或不再使用 | 理由、現況照片與建議處置 | 建立盤點、紅牌、改善、歷程與待通知 |

### 10.3 紅牌建立後立即動作

1. 記錄系統顯示的紅牌編號 `5S-RP-...`。
2. 將非必要品移到核准紅牌暫存區；第一階段預設為「A9 紅牌暫存區」。
3. 於實物標示紅牌編號、物品、數量、責任部門、掛牌日與預定處置日。
4. 物品不可立即移動時，於原位隔離、標示並記錄理由與臨時控制。
5. 確認紅牌為「待處置」、期限為掛牌日起 30 日，並有連動改善單號。

## 十一、SOP-08｜紅牌暫存、處置與結案

### 11.1 處理流程

1. 在「紅牌」以「未結案」或「逾期」篩選，點開紅牌卡片。
2. 核對紅牌編號、區域、物品、數量、原因、暫存位置、處置建議與期限。
3. 責任人點選「開始處理」，狀態由「待處置」轉為「處理中」。
4. 依權屬完成移轉、退庫、返還保管單位、核准保留、報廢、回收或其他核准處置。
5. 涉及固定資產、客戶財產、檢量具、化學品、環安衛或財務帳務時，先完成原規定會辦與核准。
6. 完成後由主管或區域負責人在「處置結果／說明」填實際結果，點「完成並結案」。
7. 確認已寫入實際處置日、處置結果證據與複查人；連動改善單同步結案。

### 11.2 結案證據

| 處置方式 | 至少應保留的證據 | 不可結案的情況 |
|---|---|---|
| 移轉 | 新位置、接收單位或負責人、現況說明 | 只移到另一個未管制區域 |
| 退庫／返還 | 收受單位、日期、數量與收受人 | 實物仍留在紅牌區 |
| 報廢／回收 | 核准、會辦、處置日與實際結果 | 尚未核准或只有建議報廢 |
| 核准保留 | 理由、上限、新定位、責任人與核准人 | 保留後仍無定位或上限 |

## 十二、SOP-09｜離線送出與恢復補送

### 12.1 離線允許與限制

畫面顯示「離線」時，PWA 可將網路錯誤或逾時的新增、更新工作寫入 IndexedDB「待同步佇列」。為避免多人同時更新舊列號造成衝突，離線時優先執行新巡檢與新盤點；改善驗證、紅牌結案與主檔變更應優先在線執行。

### 12.2 離線作業

1. 依正常步驟完成巡檢或盤點，等待系統顯示結果。
2. 記錄單號、時間、裝置與「離線排隊」筆數。
3. 不因離線排隊而重做同一張巡檢或重複儲存同一物品。
4. 補送前不清除瀏覽器資料、不卸載 PWA、不還原手機。

### 12.3 網路恢復後補送

1. 確認連線狀態為「在線」。系統會自動嘗試同步，使用人仍應進入「設定」核對。
2. 查看「離線同步」的待同步筆數；大於 0 時點「立即同步」。
3. 等待「同步完成：成功、失敗、剩餘」，目標為失敗 0、剩餘 0。
4. 點「清除快取並更新」，以單號回讀巡檢、改善或紅牌資料，確認無重複、缺列或錯列。
5. 待同步不減、失敗大於 0 或回讀異常時，停止再同步，進入 SOP-12。

### 12.4 補送失敗證據

| 必留項目 | 範例 |
|---|---|
| 畫面 | 待同步筆數、成功／失敗／剩餘、錯誤訊息 |
| 業務識別 | 巡檢單號、改善單號、紅牌編號或盤點編號 |
| 操作環境 | 工號、裝置、瀏覽器／PWA、網路、日期時間 |
| 重現步驟 | 從哪一頁、點哪個按鈕、何時出現異常 |

## 十三、SOP-10｜LINE 待通知處理

### 13.1 通知建立條件

| 場景 | 前端寫入 | 去重鍵 | 預期收件人 |
|---|---|---|---|
| 0 分重大巡檢異常 | `5S_通知紀錄`／重大巡檢異常／待發送 | 巡檢單號＋項目代碼 | 區域 LINE 群組 |
| 新增非必要品紅牌 | `5S_通知紀錄`／新增紅牌／待發送 | 紅牌編號 | 區域 LINE 群組 |

### 13.2 啟用與日常處理

1. 每一區域 LINE 群組識別碼由區域主管與 LINE 群組管理者雙人確認。
2. 使用單筆測試資料驗證收件對象與內容，未通過前保持不發送。
3. 使用既有 NEXUS OS 唯一 LINE Bot 與既有發送函式，不另建第二個 Bot、Token 或入口。
4. 建立每小時處理待通知的觸發器。成功為「已發送」；無收件對象為「待設定」；異常為「發送失敗」並留錯誤訊息。
5. 人身安全、重大品質、停線或生產中斷不等待自動觸發器，立即依緊急通報程序升級。

### 13.3 誤發或異常

- 立即停用待通知觸發器，保留通知編號、去重鍵、收件識別碼、送出時間與訊息內容。
- 不刪除錯誤訊息或通知紀錄；先確認收件識別碼、去重鍵、發送函式或觸發器問題。
- 修正後先用指定測試群組驗收，再恢復正式觸發器。

## 十四、SOP-11｜週、月 KPI 複盤

### 14.1 每週複盤

1. 統計應巡、已巡與未巡區域，核對巡檢完成率。
2. 檢視平均得分率、0 分重大異常、新增改善、未結改善與逾期案件。
3. 以改善單號逐案確認責任、期限、臨時對策、驗證人與下一動作。
4. 檢視新增紅牌、暫存天數、逾期、會辦狀態與處置結果。
5. 檢視離線同步、資料錯列、照片、權限與 LINE 通知異常。

### 14.2 每月複盤

| 主題 | 必看指標 | 管理問題 | 決議輸出 |
|---|---|---|---|
| 執行穩定 | 巡檢完成率、平均得分率、同步成功率 | 基準、頻率或系統是否可持續 | 基準調整、訓練、裝置或系統資源 |
| 改善閉環 | 準時結案率、逾期占比、重複異常率 | 是否治標未治本 | 防再發、水平展開、工程或採購案 |
| 紅牌處置 | 準時處置率、逾期數、保留比例 | 是否只轉移未處置 | 資產會辦、庫存、報廢與保留上限 |
| 展開決策 | 示範區穩定度、判定一致性、資源負荷 | 是否具備複製條件 | 展開區域、負責人、教官與驗收日 |

### 14.3 分數使用界線

分數與排名用於找趨勢、複製經驗與分配改善資源。基準、巡檢次數、項目難度、班別與區域條件未一致前，不得作為個人績效、獎懲或跨區直接排名。

## 十五、SOP-12｜系統異常、資料修正與版本變更

### 15.1 使用人異常回報

遇到無法登入、核心資料無法載入、待同步無法清空、照片失敗、錯列、重複補送、權限異常或 LINE 誤發時：

1. 停止重複點擊、送出、人工補列或刪除資料。
2. 保留畫面、錯誤訊息、單號、日期時間、工號、裝置、網路與操作步驟。
3. 通知區域負責人與系統管理員；安全或品質事件同步依緊急程序通報。

### 15.2 系統管理員診斷順序

| 順序 | 檢查對象 | 檢查內容 | 允許動作 |
|---|---|---|---|
| 1 | 入口與版本 | PWA 1.0.2、快取 v102、GAS 部署 16 | 重現、清快取、核對部署 |
| 2 | 登入資料 | `sheetData` → `01_人員主檔` → headers／rows → 登入解析 | 修正主檔或回傳格式 |
| 3 | 業務單號 | 單號、分頁、列號、原值、狀態歷程 | 辨識重複、缺列或錯列 |
| 4 | 離線佇列 | 工作類型、嘗試次數、最後錯誤與列號 | 備份證據後決定補送或修正 |
| 5 | 通知 | 編號、去重鍵、收件識別碼、狀態與錯誤 | 暫停觸發器、修正後單筆測試 |

### 15.3 資料修正原則

- 一般作業由 PWA 經正式 API 新增或更新，不以人工插列、搬移列或改變欄位順序處理。
- 修正錯列或同步異常時，保留原值、新值、原因、執行人與時間。
- `updateRow` 只允許更新 `5S_` 分頁，不擴權到無關主檔。
- 已結案紀錄不以刪除修正；必要時建立新案件或修正歷程。

### 15.4 版本變更與部署

1. 以 Git 建立變更，記錄需求、影響、驗收與部署結果。
2. 先使用 `SYSTEM-5S-TEST` 或「智慧 5S 自動驗收」資料完成靜態、寫入、狀態、離線與 LINE 驗收。
3. 通過後再更新 GAS 部署、PWA 快取查詢版本、正式入口與受控文件。
4. 部署後從正式入口抽驗登入、巡檢、改善、驗證、紅牌、離線補送與回讀。
5. 狀態字典、欄位、權限、期限或通知邏輯變更時，同步更新管理辦法、SOP 與相關手冊。
