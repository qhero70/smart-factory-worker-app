# 化新精密｜智慧5S v1.3.9｜56筆離線同步修復部署紀錄

## 問題現象

- PWA 顯示目前在線，但「待同步 56」。
- 手動立即同步後顯示「成功 0、失敗 56、剩餘 56」。
- 同步進度執行中即持續累加失敗筆數。
- 讀取中央資料正常，故障集中在 POST 寫入路由。

## 根因

正式 `doPost` v1.9.4 僅直接接手報工 V4；非 LINE、非 V4 的 PWA POST 交回 `doPost_舊版備份`。智慧5S PWA 的 `appendRow`／`新增分頁資料` 因此沒有穩定命中智慧5S寫入處理器。

既有 `智慧5S管理平台_完整後端.gs` 的 `智慧5S_嘗試處理動作_` 已處理 `updateRow` 與智慧5S專用動作，但沒有直接處理 `appendRow`。

## 已完成修復

### 1. 新增安全 POST 寫入層

檔案：

`smart-factory-command-center/01_GAS後端/智慧5S_POST寫入修復_v1390.gs`

功能：

- 支援 `appendRow` 與 `新增分頁資料`。
- 支援 `action／動作／api` 三種動作欄位。
- 支援 `headers／欄位`、`values／值`、`資料` 物件。
- 僅允許 `5S_` 開頭分頁。
- 主庫鎖定為 `19osmTlQQ9obDmVvmv5uphFHRwCtd2pkFhe6p3pYMSn8`。
- 依巡檢單號、明細編號、改善單號、歷程編號、盤點編號、紅牌編號、處置單號、照片編號等主鍵防重。
- 重送已存在主鍵時回傳成功與原列號，不重複新增。
- 使用 ScriptLock 避免同時寫入撞列。
- 依正式表頭對齊欄位，避免欄位順序差異造成錯欄。

### 2. 正式 doPost 提前接線

檔案：

`smart-factory-command-center/01_GAS後端/總控_38_6_doPost最終接線.gs`

版本：`v1.9.5`

執行順序改為：

1. 智慧5S安全 POST 接收器。
2. 報工 V4 正式接收器。
3. LINE Webhook 新模組分派。
4. 其他既有功能回交 `doPost_舊版備份`。

智慧5S接收器遇到 LINE `events` 會直接略過，不攔截 LINE Webhook。

## 正式 GAS 部署必要條件

Apps Script 正式專案必須同時包含：

1. `智慧5S管理平台_完整後端.gs`
2. `智慧5S_POST寫入修復_v1390.gs`
3. 更新後的 `總控_38_6_doPost最終接線.gs` v1.9.5

完成儲存後，需將目前使用中的同一個 Web App 建立「新版本」並更新部署；PWA 後端網址維持原 `/exec`，不可另開第二入口。

## 驗收規則

部署前：不要清除 Safari／PWA 網站資料、快取或 IndexedDB，以免 56 筆待同步資料遺失。

部署完成後：

1. 開啟智慧5S → 設定。
2. 確認仍顯示「待同步 56」。
3. 按「立即同步」。
4. 期望結果：`成功 56、失敗 0、剩餘 0`。
5. 回中央主資料庫確認各 5S 分頁實際新增資料，而不是只看前端通知。
6. 若部分資料過去曾寫入但手機未收到成功回應，主鍵防重會回傳既有列為成功，不會重複建立。

## 禁止事項

- 不清除 PWA 快取／網站資料。
- 不刪除待同步佇列。
- 不更換正式主資料庫。
- 不建立第二個 GAS Web App 入口。
- 不改動 LINE Bot 唯一入口。
